# 通用抽取协议 v2（后续对照模板，本轮未执行）

输入：有block_id、文献ID与text的原文块，以及明确标明出处的可选回读块。抽取范围只限所提供材料。不读取旧领域类型表；若在冻结模式实验中使用，则额外传入同一版本的标签字典，并将未覆盖项标为候选，不能硬套。

任务：发现可追溯提及与原子事实。领域类型和关系可提出候选名称与定义，不能把它们当作已经成立的本体。

1. 提及必须逐字引用，分开保存每次出现；同义/缩写只提出有依据的映射，不直接覆盖原文。身份不确定也可保留事实。
2. 每个事实只表达一个明确的作用、结果或阶段；同一句有多个作用时分别记录，用fact_group标明共同来源。共同条件通过有出处的引用共享，不复制后改写。
3. 参与者须带语义角色（如施事/受作用对象/被测对象/参照对象；角色名可按原文提出），并引用mention_id。没有明确作用者时留unknown，不用常识补。
4. 关系标签用于归一；relation_spans则只能是原文片段数组，分别给block_id和逐字text。非连续触发词分开保存，不用省略号拼成伪原文。字符偏移由程序对齐，不让模型估算；有多处同文须保留歧义。
5. 条件和数字分别说明属于哪个参与者、结果或阶段，保留raw及证据引用。不换算、不补值、不把背景段全部条件默认继承给所有实验。
6. 分开记录表达立场（asserted/tentative/future/unknown）、否定或无效果（negated/no_effect/none/unknown）、结果来源方式（measured/computed/unspecified，可多项）与研究归属（this_study/prior_study/review_summary/unknown）。依据不足就unknown；不要用一个高confidence替代这些区别。
7. 为每个关键论元提供证据片段；另列未解析指代、缺失条件和需要回读的位置。提出回读请求不代表已找到依据。

输出通用JSON：

```json
{
  "mentions": [{"id":"m1","block_id":"...","text":"逐字提及","candidate_type":{"name":"候选名","definition":"定义"}}],
  "facts": [{"id":"f1","fact_group":"g1","relation":{"candidate_label":"...","definition":"...","spans":[{"block_id":"...","text":"逐字关系词组"}]},"arguments":[{"role":"语义角色","mention_id":"m1"}],"context":[{"name":"条件/阶段名","raw":"逐字原文","applies_to":["m1"],"evidence":[{"block_id":"...","text":"逐字片段"}]}],"stance":"unknown","negation":"unknown","evidence_modes":["unspecified"],"attribution":"unknown","evidence":[{"block_id":"...","text":"逐字片段"}],"unresolved":[]}],
  "alias_candidates": [],
  "readback_requests": [],
  "unresolved": []
}
```

复核者逐项回读而非只回答“正确”：参与者角色是否有依据；处理阶段是否错配；关系标签是否比原文更强；数字和单位来自哪里；共享条件是否真的适用；假设/未来建议是否被当成既成事实；原文是否存在重要遗漏。程序检查字段、引用ID和逐字片段；原子性及科学含义需要语义审查，不能因JSON合法而放行。

该模板是对试跑失败的协议改进提案；未做与v1的同模型受控对照，不声称降低了错误或提高了召回。正式比较应锁定同一输入和模型、记录额外调用成本，并使用独立人工标注。
