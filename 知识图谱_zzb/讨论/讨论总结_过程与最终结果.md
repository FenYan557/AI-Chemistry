# 知识图谱讨论总结：过程与最终结果

整理日期：2026-10-19。范围：本轮会话和现存讨论文档。本文是统一阅读入口与阶段结论，不是已完成的 Schema、算法或实验论文。

## 一、最后得到的两项结果

本轮讨论最终形成两项结果：**一是实体与关系如何选择的策略，二是实际抽取方法如何选择的建议。** 两者分别回答“抽取和组织什么”以及“用什么办法抽取”，不能混为一个方法排行榜。

| 结果 | 明确结论 | 当前状态 |
| --- | --- | --- |
| 实体与关系的选择策略 | 文献驱动、开放发现、定义归一、按语义与关联需求确定边界；保留条件与证据，按需扩展 | 形成可执行策略；不是已经冻结的实体关系表 |
| 实际抽取方法选择 | 梳理直接/分步 LLM、BERT 类监督抽取，以及最后讨论的现成论文方法；方向确定为可迁移、可复现、语料驱动并保留条件与证据，具体方法未定 | 形成方向与候选建议；尚未最终选型、复现或获得领域性能排名 |

这里按讨论顺序分成三个板块：LLM 抽取、BERT 抽取、最后讨论的论文方法选型。第三板块主要也是 LLM 相关方法，是对具体流程的进一步选择，与前两项并非互斥技术分类。规则/词典只作为辅助实现，不是用户所指的第三板块。

共同前提：目标是辅助大模型广泛答疑、解释与建议；电镀及相关材料文献是首批事实来源，补充知识与建议须与文献事实区分。旧 Schema 仅作参考，不继承其类型、数量和兼容约束。没有预制问答案例不妨碍启动；用户时间紧，暂不开展大规模模型对照。

以下先保留讨论过程，再分别给出这两项结果的具体做法。**“推荐采用”与“已经实施验证”分别标明。**

## 二、讨论是怎样推进的

| 阶段 | 用户关注点 | 讨论形成的认识 | 对应材料 |
| --- | --- | --- | --- |
| 1. 审视旧方案 | 硬约束是否太强，实体是否过多，补关系是否使图过复杂 | 复杂度使用户难以看全和判断，不能只继续修补关系 | 旧资料保存在 ../旧版本/schema/ 与 ../旧版本/_archive/ |

| 5. 转向可迁移方法 | 需要可复现、可写论文，可用 BERT 或 LLM | 分开“模式归纳”与“给定模式抽取”，设计候选发现、归一、抽取及评价协议 | [抽取方法与实验协议](02_抽取方法与试跑/可迁移知识抽取方法_优化方案与实验协议.md) |

| 7. 收缩近期工作量 | 时间紧，无法做对照，先找较新且较好的现成方法 | 从完整实验矩阵转向成熟方法选型，讨论 AutoSchemaKG 的原理与边界 | 当前会话；后续方法比较稿 |

这是一条“问题收敛”的过程：从实体/关系数量，转到选择依据，再转到可复用方法，最后根据时间约束缩小近期实施范围。

## 三、结果一：实体与关系的选择策略

### 1. 总体策略

**采用“从文献事实出发，开放产生候选，依据定义和实例归一，再以信息保真与关联需求决定表示”的策略。** 不先由 AI 凭经验指定一套完整领域清单，也不把模型生成的所有标签直接变成 Schema。

| 步骤 | 实际怎么做 | 应留下什么 |
| --- | --- | --- |
| 文献驱动发现 | 从原文识别对象、事实、参与者、条件及来源，提出候选标签；不预设旧版领域类型 | 原始提及、候选事实、原文位置 |
| 定义与归一 | 为候选补定义、实例与反例；区分同义、上下位、相关但不同、不确定 | 可回退的候选到规范标签映射及理由 |
| 决定实体边界 | 判断是否需要独立身份、独立关联或反复引用；仅作属性会否丢失关键区别 | 作为实体、属性、上下文或暂缓项的决定 |
| 决定关系表达 | 明确参与角色、方向、条件和陈述性质；简单联系用二元关系，复杂事实按需用限定字段或事件/研究记录 | 条件与结果归属清楚、带证据的关系记录 |
| 审查与版本化 | 检查错误合并、条件丢失和无依据关系；保留不确定项；到实施或正式评测阶段再固定版本 | 模式字典、修改记录、待核验项 |

上表是可迁移的流程：换领域时更换语料和候选，而不是机械搬用同一套实体名称。是否有效仍需实际验证。

### 2. 实体选择的具体判据

一个对象是否独立建实体，主要看三个问题：是否有必须区分的身份；是否需要独立参与关系；仅存属性是否会丢掉重要语义。

例如，物质种类不等于具体薄膜样品，DFT 方法不等于一次 DFT 计算，计算也不等于计算得到的吸附能。语义上应区分，实现上可先用字段或子类，不要求全部扩成顶层节点。

浓度、温度、pH、数值、单位和使用角色通常先按带归属的字段保存；出现独立引用或复杂关联需求时再考虑升级表示。出现频次只用于排序，不作为排除关键长尾信息的依据。

### 3. 关系选择的具体判据

关系须有明确含义、参与者、方向及出处，并保留使结论成立的条件。共同使用不自动等于协同，作者解释不自动等于因果，局部更好不自动等于全局更优。

同一添加剂在不同浓度下促进或抑制，应分别绑定条件；不能合并成一个永久角色。实验观察、计算结果、机理假说与未来设想应能区分。

复杂事实不强塞入裸三元组，也不要求所有边都实体化；按需采用边属性、嵌套记录、研究记录或事件，避免同时丢失信息和增加无必要层次。

### 4. 九类候选的最终地位

早期提出的物质、体系、研究记录、研究对象、结果记录、方法、结构特征、作用过程、文献，是六篇样本文献得到的组织入口，**不是最后确定的九类实体**，也未作为开放发现试跑的种子。

最终保留的是上述选择策略，而非九类数量。新类型须有原文实例和增加理由；能用已有字段、词表或映射表达的，不重复增加类型。详细理论依据见[实体与关系选择策略](01_Schema重建/实体与关系选择策略_理论方法稿.md)。

## 四、结果二：实际抽取方法——方向已确定，具体方法尚未确定

### 1. 已确定的方向是什么

后续采用的方法应当能从文献事实出发发现或适配实体关系，具有明确步骤、可追溯中间结果和可复用实现；不由 AI 一次性凭经验决定完整清单。条件、结果归属、陈述性质及来源证据应被保留，复杂事实不强塞成丢失限定的裸三元组。

**确定的是选择要求和推进方向，不是“已经采用某个模型或框架”。** 用户希望方法可迁移、可复现并能据实写入论文，同时时间紧，近期不开展全面对照。因此优先评估现成论文及实现能否适配，避免同时从头开发多条路线。

### 2. LLM 抽取：已有可行性探索，具体流程仍可选择

直接结构化抽取，是把原文与记录要求输入 LLM，一次生成实体、关系、条件和证据。分步抽取则先发现提及和事实，再处理指代、组装关系、回读条件并检查；两种方式均需保留原始输出，不以模型自评证明正确。

它们适合探索缺少成熟标签的语料。当前自定义协议已完成小规模候选发现与归一试跑，但尚不能证明分步法更准确，也不等于复现了 AutoSchemaKG 或 EDC。

**建议**：保留直接/分步 LLM 作为可以理解和核查的基础方案，优先了解现成论文是否已提供这些环节，不再默认自行增加大量提示步骤。若采用远端模型，记录实际模型、提示词、输入和输出，并说明版本不可完全锁定的限制。

### 3. BERT 类监督抽取：保留路线，近期不作为优先实施项

典型流程是先确定标签并标注训练样本，再用 BERT/SciBERT 等编码器做实体识别和关系分类，可参考 PURE 的实体到关系抽取设计。它解决的是给定类型下如何抽取实例，不自动解决领域实体关系集合如何发现。

**建议**：当前标签和标注尚不具备、时间又紧，暂不启动专门训练或为凑对照安排实验。后续模式稳定、获得足够标注且需要重复批量抽取时，再评估监督路线。现有科学信息抽取数据集可借鉴规范，不能直接把其领域标签当作电镀标签。

当前未训练 BERT，也没有可用于比较的性能数据。

### 4. 最后讨论的论文方法：作为下一步选型重点

这些论文将 LLM 抽取组织成不同的建图、归一或修正流程。以下是任务适配建议，不是实测效果排序，也不代表已经选择其中任何一个。

| 论文方法 | 主要用途 | 对本项目的建议 | 需核对的边界 |
| --- | --- | --- | --- |
| AutoSchemaKG | 抽取实体/事件，并通过概念化归纳类型 | 作为完整“自动发现类型＋组织知识”路线的重点候选 | 是否保留科学条件与陈述性质；概念层会否增加不必要复杂度；Schema 对齐不等于抽取准确 |
| EDC 基础 self-canonicalization | 开放抽取、生成关系定义、检索并判断等价后归一 | 作为范围较清楚、便于查看关系定义和合并理由的重点候选 | 主要归一关系，不完整解决实体类型发现与实体消歧；EDC+R 有额外训练需求 |
| iText2KG | 增量抽取与实体/关系整合 | 文献持续增加、重复整合成为实际问题时优先参考 | 蒸馏可能损失限定，阈值相似不能证明实体相同；需固定对应论文实现版本 |
| SAC-KG | 生成、规则校验、限制递归扩展 | 用来参考错误分类和停止扩展的设计，不优先重建全框架 | 规则不是科学真值判据；完整流程包含训练依赖 |
| GraphRefine | 对草图三元组保留、删除、纠错和改写 | 事实歪曲成为明确问题时，作为修正方法参考 | 是训练型 refiner，不负责完整 Schema 发现；本轮未确认可直接部署的官方权重 |
| DIAL-KG | 三元组/事件双轨、治理与 Schema 演化 | 作为后续扩展和研究方向参考，暂不优先落地 | 本轮按预印本讨论，未确认正式版本及可用实现；系统复杂度较高 |

论文原文、实现状态及讨论依据见[相近方法比较](03_现成方法选型/AutoSchemaKG相近方法_论文比较与讨论.md)。这些是候选或参考，不是要求将六套框架同时组合。

### 5. 当前给出的具体建议

**第一优先：围绕 AutoSchemaKG 和 EDC 基础版做选型判断。** 如果先要解决“实体、事件及其类别如何自动组织”，重点考察 AutoSchemaKG；如果先要解决“开放抽取后的关系怎样定义、归一并让人看懂”，重点考察 EDC。不能因为 EDC 更聚焦就宣称它全面更好，也不能因为 AutoSchemaKG 规模大就直接认定适合电镀。

**建议的选型依据**是现成实现能否读入已有文献块、能否保留条件及来源、能否查看和撤销合并、版本与依赖是否可以记录，以及调用和修改成本是否可接受。可先在已有试跑片段上检查这些具体要求，不需要用户补问答案例，也不意味着开展全面性能对照。

选定一个主干后再小范围适配。规则可用于格式、单位和引用的一致性检查，但只是辅助，不作为第三条主要研究路线。若将来出现增量、扩展或事实纠错的明确问题，再参考其他论文的对应环节。

**当前结论：方向确定，候选集中，方法未定。** 建议优先复用可审查的 LLM 论文流程，AutoSchemaKG 与 EDC 为重点候选；BERT 保留为有标注后再考虑的路线。后续选择须依据实际适配情况，不在总结中提前写成已经采用、复现成功或效果最优。

## 六、DeepSeek 讨论的实际作用

DeepSeek 用于理论评议、对照方案和质疑，不是独立事实裁判。主要采纳了身份区分、条件绑定、记录中间层、限制性能主张等建议。

经讨论修正或未采用的说法包括：

- 不将预制问答案例设为启动门槛。
- 不认定二元边必然丢条件；需要区分裸三元组与带限定的表达。
- 不用低频直接排除类型。
- 不把自动字段检查视为科学语义验证。
- 不从 48 篇文献数量直接断言主要瓶颈一定是实体消歧。
- 不把条件区间重叠视为事实可直接合并的充分依据。
- 不将模型间意见一致当成独立实验或学术证据。

详情见[理论讨论记录](01_Schema重建/实体关系选择_讨论与来源记录.md)、[抽取讨论记录](02_抽取方法与试跑/抽取方法_文献与DeepSeek讨论记录.md)及[选型稿第五节](03_现成方法选型/AutoSchemaKG相近方法_论文比较与讨论.md#5-与-deepseek-的讨论及主智能体裁决)。

## 七、最终结果的简明表述

**结果一——选择策略：**文献驱动发现实体与关系候选，用定义、实例与反例进行归一，依据身份、关联需求和关键语义保真决定实体、属性及关系的边界；保留条件、陈述性质与来源，按需求扩展，而不是先冻结一套复杂清单。

**结果二——抽取方法：**具体方法尚未确定，方向已明确：优先寻找可迁移、可复现且能保留科学条件与证据的现成方法。按直接/分步 LLM、BERT 类监督抽取、最后讨论的论文方法三个板块保留判断。近期重点考察 AutoSchemaKG 与 EDC 基础版，其他论文按问题参考；BERT 暂缓，规则只是辅助。

上述为本轮讨论的推荐结果，不能表述为用户已确认具体框架或已完成实证验证。本次仅修改总结，未新增模型调用、系统实现或性能实验。
