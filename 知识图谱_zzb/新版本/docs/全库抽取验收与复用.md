# 全库抽取：精确率优先的验收与复用

本轮抽取与验收已完成（2026-10-21）。工程流程可复用，但语义自动核验仍需每批独立抽检；保守版5,816事实，最终全库精确率尚未测得。实测结果及修改顺序见[验收报告](../reports/full_extraction_20261020/验收报告.md)。该文保留执行协议，不把正负对照成绩或AI通过率当作全库精确率。

## 验收顺序

1. 等首轮所有单元处理完成，核对48篇输入、源文件SHA、逐篇合并和最终schema校验。失败与部分成功单独计数，不能当成无事实。
2. 使用程序检查引句、参与者、数值、单位、比较基准、处理阶段、观测/解释性质及浓度归属。低风险只是分流判断；明确的数值或基准证据缺口进入隔离区，AI不能覆盖该规则。
3. 对有语义风险的事实调用独立核验提示，仍使用用户指定的独立Key。当前核验模型为qwen3.7-plus，非思考模式；抽取模型仍为qwen3.6-plus。不同别名不保证真实上游独立，因此还要主智能体复查。
4. 随机抽核低风险组120条。若超过2%未获AI支持，就扩大检查到其余低风险组。未支持不等于已经证明错误，筛选时先隔离。
5. 主智能体独立复查分层样本及少量疑难案例。原始判读包不显示AI判断；保留复查理由和原文。这里的“主侧复查”仍是AI审阅，不冒充领域专家人工金标。
6. 对空结果/失败科学文本、达到8条上限的块和普通非空块，各抽最多12个单元找遗漏。只生成待核查补充线索，不凭这个便利样本给出全库召回率。
7. 原始图谱保持原样，另存筛选后的precision_graph及隔离记录。主复查完成后才形成最终验收结论。

## 已执行的方法检查

- 14个盲编号受控案例来自真实文献，4个正确例、10个数值/单位/对象/阶段/性质/基准错误例。AI核验4个正确例均通过，检出9个错误，漏掉1个错误比较基准；程序规则补足该缺口，组合检查4个正确例保留、10个错误例隔离。这不是总体精确率估计。
- 批处理曾把合法的空抽取结果送入不允许空事实的图谱契约，已区分“无事实单元”和“空图谱”。保留schema约束并加回归测试，没有用放宽schema掩盖错误。
- 后半段47篇完成后，单篇长文导致线程空闲。调度已改为小批并发和轮转排队，并从检查点恢复；相关测试确认单篇也可使用多个线程。
- 检查点与协议、模型、来源指纹绑定；既有事实和失败历史保留，不靠覆盖源文献清除错误。
- 保守格式归一只允许Unicode兼容字符、空白与负号字形对齐，禁止改变大小写、数字、词序或填充省略号；有多个可能位置时拒绝自动匹配。可恢复条目仍是候选，需语义检查后才能纳入。

## 以后怎么运行

同一库中断后，使用同一run目录，已完成的单元与AI判断不会重复调用。新增文献或来源内容变更时使用新目录，可显式复用未变化文献的旧缓存：

```powershell
python -B -X utf8 scripts/knowledge_pipeline.py --run reports/下一批 --reuse-from reports/full_extraction_20261020
```

复用要求文献ID、SHA和单元ID一致，抽取模型与协议兼容；不复制Key或全局配置。更改模型/抽取协议时不复用不兼容缓存。旧partial/failed状态原样保留，如需重试必须显式加`--retry-failed`。

先查看执行计划，不产生调用：

```powershell
python -B -X utf8 scripts/knowledge_pipeline.py --run reports/下一批 --reuse-from reports/full_extraction_20261020 --dry-run
```

这是一键执行自动阶段的入口。是否能够减少后续复查、当前抽样支持率及剩余错误类型，以本轮实际报告为准；不能以脚本能跑通就认定无需抽检。


## 本轮补齐的复用条件

- 自动入口依次执行首轮抽取、规则分流、AI核验、定向语义复核、有限遗漏检查、格式锚点恢复、保守语义降级、补充候选核验和最终合并。
- 数值、单位、比较基准缺乏引文证据时，程序直接隔离；AI的“支持”不能覆盖该规则。
- 低风险抽查不达标时自动扩大核验，不能默认正则命中就可靠。
- 将实验方法改成报告陈述等保守降级保留原记录与替代关系；禁止悄悄改动数值、单位和来源。
- 同批次判断缓存绑定核验提示和模型；遗漏检查缓存还绑定源文、已有事实与请求参数，新增事实后旧遗漏结果失效。
- 新批次只继承未变化文献的抽取和兼容核验缓存；旧批次的主侧通过结论不自动作为新批次独立抽检。
- 正式抽检文件缺少标签、重复标签或来源已变化时，不标为完成。主侧复查仍是AI判断，需要时另做领域专家金标。
- 已用2篇真实文献、239单元回放，546条事实ID完全一致，网络调用为0；48份来源文件及98份CSV的SHA均与冻结清单一致。

抽取、定向核验、补充核验各有独立检查点。认证或路由失败保留检查点并停止，不切换到其他Key。未来的模型参数可用`--judge-model`指定；核验效果要按新模型重新校准，不能沿用本轮模型的成绩。
