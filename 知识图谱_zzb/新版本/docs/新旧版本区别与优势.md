# 新版 v4 与邻近旧版 v1.1 的区别及优势

本文比较的是当前“新版本”目录中的4.0.0-draft，与邻近“旧版本/schema”目录中的v1.1，不是将新版v4仅与它之前的v3草稿比较。依据为两边实际Schema、抽取契约、校验说明与脚本；没有重新开展模型性能或准确率对照实验。

## 一、两个版本分别想解决什么

旧版v1.1以完整的电镀添加剂选型知识体系为设计目标。它将来源、观测、实验、概念和知识聚合分层组织，预先考虑工艺窗口、结构基元、机理链、冲突和多篇共识。其设计范围覆盖了建库后进一步比较、聚合和推荐所需的较多环节。

新版v4以当前工程的实际条件为起点：几十篇专题文献、最终模型未定、优先采用A2lab-key可连接的便宜模型，以及希望回答自然直接。它首先让具体事实、条件和证据能够可靠保存，再通过代码生成必要图视图，回答时结合模型知识进行机理分析和候选建议。

两者都面向条件化、可溯源的科研知识，并不是“旧版只有三元组、新版才增加属性和证据”。旧版本来就有值对象、多元实验上下文和来源锚点。

## 二、结构与实现的主要差异

| 方面 | 旧版v1.1 | 当前新版v4 | 对本项目的意义 |
| --- | --- | --- | --- |
| 总体组织 | 来源、观测、事件、概念、知识五层，含显式Claim与Observation分离及EvidenceLink | 以文献事实记录为中心，按需连接条件、结果、运行、样品；图为派生视图 | 减少初次抽取时要同时组织的对象和连接 |
| 类型与关系规模 | 24类节点、34类结构边、16个断言谓词 | 后台39类候选类型、14个记录集合、14种领域关系目录，其中3种启用 | 统计口径不同，不能用24与39直接证明新版更简单或更完整 |
| 模型输出 | 断言JSONL，顶层12项必填，主客体还有类型等嵌套字段 | 独立精简抽取，每条事实4项必填；完整内部事实6项必填 | 便宜模型集中处理字面对象、作用、陈述性质和引句 |
| 模型与代码分工 | 已规定抽取不造最终图节点ID，后续归一化独立进行 | 进一步提供精简导入接口，代码定位引句、生成ID、补默认字段、校验与投影 | 新版延续并落实已有思路，不把ID交给代码说成全新发明 |
| 实验上下文 | Experiment、Run、AdditiveUsage、Observation及工艺窗口是较完整主干 | Experiment、Run、Sample等按事实需要展开；无具体实验的解释不强造Run | 更容易容纳摘要、定性结论、机理与展望 |
| 功能角色 | 已有角色词表，角色通过特定使用语境挂接，不直接成为物质永久标签 | 功能角色记录绑定事实、主体、证据和条件 | 主要区别是记录组织和抽取负担，不是从无到有改成枚举 |
| 数值表示 | 已设计点、区间、上下限、开闭区间、不确定度及工艺窗口 | 先保存原始数值或定性内容、单位状态、阶段与基准证据 | 新版更易开始记录，但数值表达的丰富性并不全面超过旧版 |
| 条件比较与聚合 | comparability_key、有效窗口、KnowledgeUnit、Conflict等均有设计 | 按具体用途核对条件、单位和基准；自动窗口、共识、冲突裁决后置 | 不在小库起步阶段预先承担完整聚合系统的成本 |
| 机理与类比 | 已设计Mechanism、Motif、EXPLAINS、SIMILAR_TO及类比谓词 | 作者解释保存为事实；允许回答模型结合证据与知识提出机理推断和库外类比候选 | 可以先支持机理讨论，不要求已建成显式机理图；但不等于具备同等图查询能力 |
| 关系开放性 | 谓词需登记；新谓词可以进入待审，未登记参数等另有较严格约束 | 未规范关系与单篇发现保留为事实，不自动禁止忠实引用；没有角色投影则不生成规范边 | 减少新发现被规范化进度卡住的情况 |
| 校验与使用资格 | reject、downgrade、warn三档，并结合T1至T4证据等级与检索资格 | block、review、warn三档；引用、数值比较、机理分析、候选建议分别判断 | 新版不是首次引入三档，而是调整内部状态与回答用途的关系 |
| 证据定位 | 已有块、表格单元格、图和公式等锚点设计 | 当前可执行契约主要实现块内逐字偏移与表格单元格核对，基准可有独立证据 | 新版定位明确、可验证，但不能声称图和公式锚点支持更完整 |
| 回答输入 | 定义检索结果字段、资格和框架适配约定，正式查询与问答尚未交付 | 提供自然语言证据卡、简短引用和代码侧完整回指接口 | 更直接服务当前回答流程，内部审核与类型目录不必灌入模型 |

旧版抽取契约的12项必填包括断言标识、类别、文献、主语、谓词、宾语、极性、立场、证据等级、锚点、抽取器及审核。新版精简抽取的4项是主体、关系粗分类、陈述性质和逐字引句；对象、条件及结果按需要补充。这里比较的是两个抽取接口，不是用旧版内部全部字段与新版最简示例作不等口径比较。

## 三、新版当前启用什么，哪些内容后置

新版模型任务只使用作用、吸附、测量、机理、未来工作和其他六种粗分类。前三种映射为r7“添加物对沉积过程、组织或性质的影响”、r11“吸附于表面/位点/晶面”、r9“材料或样品的性质测量”。有清楚参与者角色时，代码生成相应方向的图边。

其他关系、作者解释和展望可以保留为事实并参与原文回查，不为构成图边而强凑实体。实体、关系、属性、条件、来源及身份的具体全集见[本Schema文字详解](本schema文字详解.md)。

后台39类类型中17类为核心、22类为候选。它们并没有被整体交给抽取模型。14个记录集合也不等于14类领域实体：其中包含文献、事实、身份链接和派生视图等不同用途的集合。

旧版结构基元、显式机理链、有效窗口、多篇知识聚合、冲突裁决和相关排序设计具有参考价值；新版暂不完整实现这些内容。需要时应由真实问题驱动，逐步补回，而不是为了保持旧版清单而全部先建。

## 四、对当前工程的实际优势

### 1. 更适合便宜模型的能力下限

四项必填和单块小任务，使模型不用一次管理复杂Schema中的大量ID、审核、证据等级和嵌套关联。对已经发现的引用、数值、对象错配等错误，优先让代码检查。这个接口降低了任务要求，但不保证所有便宜模型都能稳定抽取。

### 2. 更适合小型、信息不齐全的文献库

一篇论文中的明确结果就可以被保存和引用。定性作用、新关系、只有部分条件的陈述都有位置，不需要先补齐全库身份、比较窗口和聚合结果才能开始使用。

### 3. 更容易追查一条具体结论

完整事实集中保留参与者、条件、结果和证据。派生边可以回到事实，数值基准可以回到原文；图视图与记录不一致时能够检出。保留全部来源的同时，不必把每项属性都变成图节点。

### 4. 更容易控制回答中的防御性措辞

审核和候选状态保留在后台，回答输入以自然语言证据卡呈现。引用、比较和建议分开判断：缺少跨篇支持不等于不能引用单篇结果，未登记关系不等于不能解释原文，缺基准也不等于不能报告绝对值。

这是一种降低不必要防御语言的工程设计。当前试跑仅观察到技术字段泄露改善，不能声称回答整体效果已经得到独立验证。

### 5. 保留大模型知识带来的分析价值

模型不仅复述文献，还可以解释一般背景、整合机制和提出库外类比候选。具体实验数据仍由证据提供，类比建议不能冒充已经被文献验证。这样，小文献库可以支持讨论更广的候选空间，同时保持出处边界。

## 五、新版没有取代旧版的全部优点

旧版对区间、不确定度、工艺窗口、可比性、显式机理路径和知识聚合的设计更细。如果后续目标是严格的窗口计算、自动冲突判别或结构化多跳机理查询，仅靠当前v4还不够。

旧版也已经考虑缺失状态、角色条件性、模型自评不能抬高证据等级、多条边不等于因果，以及多篇证据不能自动升级。不能把这些已有设计写成新版独有优势。

新版三处回归修复是相对于新版自身早期实现：边反向未检出、伪造基准未检出、合法缺失条件导致异常。没有针对旧版注入同样反例并验证其结果，不能据此断言旧版也存在这三处漏洞。

同样，旧版24类节点、34类边和51条约束，与新版39类后台类型、3种启用领域关系和96个检查码不是同一种计数。检查码多不等于质量更高，启用关系少也不等于原文记录必然少。

## 六、当前证据能支持到哪一步

新版已有88项测试通过，两组主要样例合计3篇4块14条事实，另有一条真实轻量模型抽取通过导入。它们证明部分结构、定位、投影和接口行为可运行，不证明全库抽取准确率或化学语义正确率。

测试模型的回答仍出现引用错配、推断过实和输出格式问题；最终接入模型尚未确定。没有完成等成本、等证据、独立隔离的新旧模型对照，因此目前不能给出“准确率提升多少”“费用降低多少”或“问答效果全面优于旧版”的结论。

选择新版作为当前工作版本，主要依据是它更贴合本阶段的工程约束，且已有一条较小的可运行记录—校验—证据输入路径。旧版保留为后续扩展时的设计参考。
