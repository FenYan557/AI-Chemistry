# 新版 schema 调整计划 v0.4：基本假设讨论稿

日期：2026-10-20。状态：历史讨论稿；已由[正式实施计划 v0.4](实施计划_v0.4.md)取代。用户已确认主要用途为添加剂候选选择与机理分析，允许基于证据提出合理推断和候选建议。下文保留讨论过程，不作为当前实施依据。

## 1 已知事实与本轮目标

已知：现有语料清单为48篇；当前schema为3.0.0-draft；示例仅3篇4块14条事实，不能据此认定全库覆盖；用户关注复杂度与LLM回答的观感。当前没有本轮回答对照实验，不能声称已证实schema造成防御性语言。

目标：使schema适合有限、专题性的电镀文献库；保住关键条件和证据，减少抽取与维护负担；让回答直接、有依据，并允许合理分析。文献少不是省略关键信息的理由；成熟产品功能也不是本工程的必做清单。

## 2 待讨论的基本假设

所有H项目前均为建议，待用户讨论；不是已确认事实。

| 编号 | 建议假设 | 设计后果 | 何时重审 |
| --- | --- | --- | --- |
| H1 | 近期是几十篇起步、渐进增补的专题库，不按通用材料百科设计 | 优先保证具体问题可回答；不为未出现需求预建全套类型/平台 | 扩展到多个明显不同领域、多人持续维护或增量更新困难时 |
| H2 | 首要价值是辅助理解添加剂的作用、条件、机理与候选选择；自动产出最佳配方不是默认目标 | 围绕实际问题设计结构；允许候选建议，保留适用条件；不先做全自动优化/推荐窗口 | 用户明确以抽取研究/图谱展示为主，或要直接生成配方时 |
| H3 | 文献是有范围的研究证据，不是完整真值库；库内没找到不等于不存在 | 回答区分“没有检索到”与“没有作用”；不用来源数量简单投票 | 接入更完整数据库、系统综述或外部知识时 |
| H4 | 单篇明确结论就有引用与讨论价值；术语规范程度、人工审核状态、研究证据强度相互独立 | 取消以至少两篇来源作为术语可用性的普遍门槛；多来源只作为支持广度，不自动增加正确性 | 对高风险操作或正式定量结论有专门证据要求时 |
| H5 | 结构化层负责关键关联与筛选，原文检索负责细节补全；无需把全文每句话都转成规范边 | 保留最小事实骨架、开放关系和原文；映射未完成只影响规范图计算，不自动禁止忠实概括 | 真实查询反复因缺字段/关系而失败时 |
| H6 | 条件依赖是本领域核心复杂度；治理和表示形式可简化，条件不能随意省略 | 最少表达对象、作用/结果、条件与出处；数值、基准、样品/处理按需展开；低频但关键信息仍保留 | 真实样例证明字段冗余或无法表达时 |
| H7 | 助手应先给直接结论、解释与引用；内部审核码和候选状态不逐项进入正文 | 分离记录契约、校验报告和回答上下文；只呈现影响用户判断的限制；不靠删除元数据改善措辞 | 用户切换到审计/证据核查模式时 |
| H8 | 允许明确归属的作者解释和有依据的助手推断，并提出待验证候选 | 推断以自然措辞区别于文献报告，不写回为原文事实；证据冲突影响选择时简短说明 | 用户要求纯摘录，或涉及具体高风险操作时 |
| H9 | 人工可以抽查关键/异常事实，但默认不逐条审核全库 | pending不等于不可引用；审核资源优先用于身份合并、关键数值/基准、影响候选选择的冲突 | 用户有足够标注人力或必须逐条验收时 |
| H10 | 当前任务是局部改造，延续现有JSON Schema与脚本，先不引入新数据库和完整平台 | 复用已有契约/示例/测试；调整新目录及必要文档；旧版本、讨论与清洗原料保持只读 | 实际存储/检索瓶颈已有证据时 |

## 3 设计原则：先避免把不同状态混在一起

- 未人工审核不等于原文含糊；缺跨篇支持不等于不能引用。
- 类型/关系尚未规范不等于对应文献事实不可靠。
- 缺比较基准会影响提升幅度计算，不必阻止报告绝对测量值。
- 可引用、可计算比较、可提出候选建议分别判断，不用一个A–E总档决定全部用途。
- 原文观测、作者解释、助手推断分别归属；不把“读起来坚定”当作正确性。
- 仅把冲突、悬空引用、错配对象、伪造基准等实际错误设为硬阻断；其余根据具体用途处理。

## 4 分阶段计划

### P0：讨论基本假设与任务边界（当前）

交付：本稿；明确主要用途、推断边界和人工维护方式。无需重做前轮成熟产品调研，无模型调用。

验收：每条假设可说明对设计的影响；未决定项显式保留。先确认高影响假设，避免一次问十个问题。

### P1：定义最小任务与记录骨架

在用户确认方向后，从真实材料挑选6–8个有代表性的问题，覆盖作用与条件、机理、候选比较、定量变化、冲突或未找到证据。不把临时固定问答集当作领域金标。

逐项检查“需要什么结构才能回答”，形成现有字段/类型/关系的保留、可选、后台派生、后置对照。核心围绕研究对象、作用/结果、关键条件、出处、陈述归属；数值/基准/样品/Run只在适用时展开。最终类型数由用途与样例决定，不凑目标数量。

验收：低/高浓度不同作用、处理前后结果、作者解释与未来工作都能表达；抽取端不必输出大量无意义null；关键低频信息不因低频被删除。

### P2：修改契约、校验与物化

调整records.schema、registry与validate/materialize；把候选治理和内容证据分开；每类关系明确参与者角色及图投影规则。优先修复已复现的反向边未检出、伪造基准未检出、absent条件导致异常三项问题。

为旧示例提供明确版本/迁移处理，保留现有来源与必要ID；不静默改写旧记录含义。根据真实字段变动决定是否需要迁移脚本，不先写通用迁移平台。

验收：旧例有明确归宿；三项反例被正确处理；已有必要测试与本轮针对性回归通过；不用测试数增长作为交付目标。

### P3：新增精简的回答消费契约

默认给回答模型：问题相关事实、关键条件、原文引用、必要的陈述归属及会改变判断的限制。完整schema、约束目录、所有审核提示不整包作为回答提示。

回答先给结论及依据；用“该研究报告”“作者解释为”“据此可优先考虑”等自然归属区分内容来源。仅在影响比较、适用性或选择时解释缺口；允许报告单篇结果、绝对值、定性效果与明确标识的推断。

范围：本目录先交付消费契约与输入输出示例；若真实问答入口在其他目录，先定位并单列接入变更，不把写了契约说成已改变线上回答。

验收：不暴露内部错误码/审核流水账；不重复通用免责声明；关键适用条件、真实冲突和数值限制仍有表达。

### P4：有界对照与修订

先用现有3篇4块及少量补充真实片段验证结构；不足之处按问题补样，不整库重抽。经用户确认后，使用同一可用模型、相同问题与证据，比较旧/新回答上下文；直接走A2lab启动器，核实已登记可用模型，限制调用规模，失败不切个人凭据。

对照维度：事实/数值是否正确、关键条件是否保留、能否直接回答、是否混淆观测与推断、是否出现无助于判断的重复防御语言。短不等于好，引用多不等于好；主侧人工读答、逐项回查来源，不虚报准确率或统计显著性。

必要时加原文RAG对照，判断结构化层究竟带来什么收益；不因已有图谱而强制每个问题走图查询。

验收：主要任务可回答且无新的关键事实错误；冗余说明减少，不以删掉必要条件换取流畅。失败项驱动一次局部修订，避免无止境调参。

### P5：更新说明与收口

同步README、可读schema、MASTER及必要示例。记录确认假设、实际修改、实际验证与剩余事项，不建立多套竞争进度文档。

## 5 当前不扩展的内容

全库抽取、外部化学库自动消歧、自动共识裁决、完整推荐窗口、企业级权限/协作UI、通用迁移平台、BERT训练与大规模模型对照，均不因本轮规划自动加入。

## 6 本轮讨论顺序

优先讨论：①主要用途是文献解读、候选选择还是抽取研究；②是否允许助手基于证据提出候选与推断；③人工审核是关键处抽查还是逐条审核。其余假设先按建议保留，随实际任务修订。用户补充会改变基本假设时先更新计划，再落实现有目录。
