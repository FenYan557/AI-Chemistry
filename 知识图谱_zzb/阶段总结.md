## 方便人工核验的方法

先看同目录的「人工核验样例.md」：已从当前正式图谱整理12条核验卡，直接列出事实、参与物、条件、结果和原文引句。它是方便检查的定向样例，不是准确率抽样估计。

每条按以下顺序检查：

1. **找原文**：按卡片文献标题在原始PDF库找到论文；优先搜索英文原文引句或独特数值。原文块page为解析器记录，可能从0计数或与印刷页码不同，应以PDF内容为准。
2. **看对象**：主语、受影响对象、参与角色、缩写和全称是否对应；特别检查是否把不同物质、不同分子量或不同水合物合并。
3. **看语气与范围**：是否把“可能”变成确定结论、“无某项影响”变成完全无效，或把引用他人研究当作本篇实验。
4. **看数字与条件**：逐项核对正负号、单位、范围、浓度、温度、pH、基准、样品和实验组。表格同时核对列标题、行标题、脚注及正文，不能只看单个单元格。
5. **记录判定**：填写“通过 / 错误 / 信息不足 / 原文冲突”，附事实ID、原文块ID、PDF页位置、错误说明及建议修改。信息不足不强行判对错；原文冲突单独记录。

检查覆盖率时应反过来：任选一段方法或一行表格，先从原文列出独立信息，再在图谱中找对应事实。只看已抽出的事实无法发现漏抽。建议先核验10条定量事实、10条否定/推测事实、10组名称归一，并分散到不同文献；这是快速排查，不是全库质量保证。

### 查询任意名称

在「新版本/」打开PowerShell，执行以下命令即可离线输出包含引文及来源ID的JSON，不调用大模型：

```powershell
python -X utf8 .\scripts\entity_resolution_retrieval.py "PVP" --limit 8 --output .\人工核验_PVP.json
```

查看输出的 evidence、conditions、outcomes 和 references。S类引用对应图谱事实，C类对应补充关系，R类是补充原文；原文共现本身不能证明关系。输出数量受limit限制，不能用一次查询判断全部覆盖率。

### 按事实ID精确查看

同样在「新版本/」运行，把示例ID替换为核验卡或查询结果中的fact_id：

```powershell
python -X utf8 .\scripts\answer_context.py .\knowledge_graph.json --fact "f:e6fb11f4a0257b0c" --audit --output .\人工核验_事实.json
```

底层数据位置：knowledge_graph.json存事实、提及和原文块；entity_graph.json存概念、别名和提及归属；relation_context.json存补充关系。registry/source_corrections.json记录原OCR块与核验摘录的映射，registry/source_conflicts.json记录已知原文冲突；docs/source_verification/提供本轮已核验的PDF页面图片。

原始PDF库位于「AI-Chemistry/知识图谱所需文献/分类文献库/」。图谱document.source_file记录的可能是抽取或清洗文件，不应直接当作PDF路径。
