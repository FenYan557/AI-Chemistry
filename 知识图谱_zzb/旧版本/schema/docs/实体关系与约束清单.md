### 1.7 实体身份的硬规则（`id_conventions.md`）

1. **禁让 LLM 输出最终 ID**：抽取期只填 `name_raw` / `run_local` / `experiment_local`，映射由归一化工序完成，可复现可重跑。
2. **禁跨篇合并** Experiment / Run / Bath；只允许跨篇合并 Chemical（经 alias + InChIKey）与 Motif（词表）。
3. **禁把文本当主键**（`SPS` 在不同篇可能指不同纯度/牌号，文本只能作别名）。
4. Chemical 的 canonical 以 **InChIKey** 为准（异构体同键、盐型不同键）；`unresolved` 保留原始写法、置信度与出现位置。
5. 值来自 `lexicon/` 的字段一旦 `ref:` 指向词表，即受 C-META-02 强制。

### 2.3 谓词语义规则（`predicate_rules`）

1. `direction` 只取 `increase | decrease | none | non_monotonic`，禁「提升/下降」这类自由文本。
2. `magnitude` 只放数值+单位；单位缺失即降级（C-UNIT-01）。
3. **禁反向谓词**：没有 `increases_eta`，只有 `affects_indicator(direction=increase)`。
4. 未登记谓词一律 `review=pending` + 进待审区，由人工决定合并还是新增（C-PRED-01，warn）。

### 2.4 关系方向与挂载的硬规则

- `HAS_ROLE` 只能从 AdditiveUsage 出发；`Chemical.charges` 只存作者命名的措辞，不是本图判定。
- `AGGREGATES` 只由 claims 生成 KU，不回写 Claim；KU 一个只能对应一个 `comparability_key`。
- `CONTRADICTS` 对称；跨口径的差异不是矛盾，`Conflict.conflict_type` 须为 `measurement_mismatch`（C-CMP-02）。
- `EXPLAINS` 必须带 `window` 或显式 `unconstrained`，`strength` 只取 strong/partial/speculative。
- 端点合法 ≠ 每一步有证据：`OPERATES_BY` / `PRECEDES` 目前没有统一的 `claim_ids` / `anchors` 必填槽（见 `docs/多跳支持与落地边界.md`）。

## 3. 值对象与派生字段上的约束

### 3.1 `presence` 三态（一切缺失判断的前提）

| 值 | 含义 | 检索中的处置 |
| --- | --- | --- |
| `reported` | 原文给了数值/区间 | 参与窗口求交 |
| `not_reported` | 原文没说 | 视为 UNKNOWN，**不得计为满足**（C-WIN-02） |
| `unconstrained` | 原文明确说不限/无关/均可 | 才算开区间，恒满足 |

### 3.2 `quantity` / `param_value` / `window`

- `quantity`：`kind=range` 时 `lo<=hi`（除非声明 open_low/open_high）；`raw` 必填用于回查；`unit` 空则该 quantity 不得支撑 T1。
- `param_value`：`param` 必须在 `lexicon/units_params.yaml#params` 登记（C-PARAM-01）；`value_kind=categorical` 的 param 只允许 `kind=categorical`；同一 window 内 `param=concentration` 出现多次时 `of` 必填。
- `window`：求交只在 reported 上做；unconstrained 恒满足；两窗口交集为空 → 输出「文献未覆盖该工况」，这是可解释的不知道，不是失败。
- 同一窗口内浓度必须同 basis（mass / molar），跨 basis 不得求交（C-UNIT-04）；单位须先归一到 canonical（C-WIN-03）。

### 3.3 `anchor`（硬门禁）

- 四类：`block` / `table_cell` / `figure` / `equation`；必带 `doc_id` + `page` + `quote`。
- `quote` 必填，block 类须与 `block.text` 归一化后子串匹配（相似度 <0.90 拒收，C-ANCHOR-02）；`block_id` 须能在清洗产物中查到（C-ANCHOR-03）。
- 表格数值**必须**锚到 `table_cell`（row/col），不许只锚整表（C-ANCHOR-04）。
- 页码一律用 PDF 页；`printed_page` 只作展示。

### 3.4 `cross_section_arg` / `defect_kind`

- `cross_section_arg`：跨节论元（`arg` + `anchor` + `section_role`），用于 DocEE 口径的单报召回。
- `defect_kind`：8 值枚举，禁自由文本；描述写 `scope_note`。

### 3.5 三个派生字段（定义已定死，计算留执行侧）

| 字段 | 定义 | 禁止 |
| --- | --- | --- |
| `comparability_key` | `{指标}\|{主方法}\|{参比电极 or na}\|{孔型 or na}\|{AR 桶 or na}\|{面积基准 or na}`；AR 桶 `AR<3 / 3<=AR<5 / AR>=5 / na` | 同 key 只是初筛必要条件，关键口径缺失仍为 UNKNOWN；缺 key 时不得退化成「就地比较」 |
| `effective_window` | 同一 (subject, predicate, indicator, direction, comparability_key) 的 reported 参数求交；`evidence_windows` 逐条保留 | 不得把 not_reported 当开区间；不得跨 key 求交；不把离散点补成连续区间 |
| `ranking` | 偏序：tier 高 → consensus>single_source → n_docs / n_independent_runs 多 → year 新（末位 tie-breaker） | v0 **禁止自造加权分数**（C-CMP-03），要用数值分必须先标定并登记权重来源 |

### 4.2 尚未机检的约束面（真正的缺口）

1. **基数 `card`**：34 条边的 `1:N / N:M / 1:1` 只是声明，`validate_graph.py` 无基数检查。
2. **边上的 qualifier**：除 `EXPLAINS`（C-EXPLAIN-01）外均未检——`HAS_MOTIF.evidence`、`SIMILAR_TO.score/method`、`OPERATES_BY.window`、`CONTAINS.param_value` 都只写在声明里。
3. **`tier_cap` 与 `claim_kind` 绑定**：注册表写了 `causes_defect` ≤T2、`analogous_to` ≤T3、`motif_improves` 单篇不得 T1，但没有 check 读这两个字段，只能靠 C-EV-01/02 通用规则间接兜底。
4. **概念边缺「必带证据」槽**：`OPERATES_BY` / `PRECEDES` 无统一 `claim_ids` / `anchors` 必填字段（`docs/多跳支持与落地边界.md`）。
5. **扩展位不查语义**：序列化约定允许未声明字段存在，但「校验器不会检查其语义」（`schema.yaml:612`）；节点内跨字段一致性目前只有 Chemical 一条。
6. **值对象的部分联动未检**：`Table.evidence/ocr_status` 与数值断言等级的联动已有，但 `Chemical.resolution_status` 与 `names/aliases` 的一致性、`Feature.ambiguous` 与 `pore_diameter` 的关系没有校验。
