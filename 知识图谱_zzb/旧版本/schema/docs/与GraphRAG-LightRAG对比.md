# 与 GraphRAG、LightRAG 的联系与区别

> 设计背景材料，保留当时的论证；当前契约与实现状态以 [README](../README.md) 和 [schema.yaml](../schema.yaml) 为准。本文的性能估计、框架比较及文献检索结论未在本次整理中重新验证，不能作为当前实测结果。可比性键仅作初筛，关键口径缺失不能证明可比。

一句话：**GraphRAG 与 LightRAG 解决"怎么把知识取出来喂给模型"，本项目解决"什么样的记录才敢被取出来用"。两者不冲突，属于上下游；但若直接拿它们的图回答选型问题，会在条件、口径、证据三处出错。**

---

## 一、三者各自在做什么

| | GraphRAG[1] | LightRAG[2] | 本项目 |
|---|---|---|---|
| 定位 | 检索/索引框架 | 检索/索引框架（轻量） | 写入契约 + 校验器 |
| 输入 | 文本语料 | 文本语料 | 已抽取的断言、清洗产物 |
| 产物 | 实体-关系图 + 社区层次 + 社区摘要 | 实体-关系图（带关键词）+ 向量索引 | `claims.jsonl`（断言）→ 节点/边/KnowledgeUnit |
| 查询模式 | 全局（社区摘要 map-reduce）、局部（实体邻域）、DRIFT | 低层（具体实体）+ 高层（主题关键词）双层 | 同口径内排序、条件求交、拒答 |
| 面向的读者 | 生成模型 | 生成模型 | 下游智能体 + 人工审计 |

GraphRAG 的流程是：文本切块 → LLM 抽实体与关系 → 社区检测（Leiden，层次化）→ 为每个社区生成摘要 → 查询时全局走摘要、局部走邻域[1]。LightRAG 的流程是：抽实体与关系并附带关键词 → 建图 + 建向量 → 查询时用关键词同时命中"实体层"和"主题层"，并支持增量插入[2]。

## 二、逐维度对比

| 维度 | GraphRAG | LightRAG | 本项目 |
|---|---|---|---|
| 数据单元 | 实体、关系、社区摘要 | 实体、关系、关键词 | `Claim`（结论）、`Observation`（测量）、`Run`（条件）、`KnowledgeUnit`（聚合） |
| 是否带实验条件 | 否（关系只有自然语言描述） | 否 | 是（`window` + `Run.conditions`，三态） |
| 是否带数值与单位 | 否（数值留在描述文本里） | 否 | 是（`Observation.value` + 单位规范化） |
| 是否带测量口径 | 否 | 否 | 是（`comparability_key` 六段，跨键禁止比较） |
| 是否带证据等级 | 否 | 否 | 是（T1–T4 + `EvidenceLink.tier`） |
| 引用粒度 | 文本块（text unit） | 文本块 | 块 / 表格单元格 / 图 / 公式，且要求引用文字回读通过 |
| 冲突处理 | 不做（多篇结论并进同一描述） | 不做 | `Conflict` 节点 + 裁决类型 |
| 更新方式 | 重建社区与摘要为主 | 支持增量插文档 | 位置哈希锚点 + `pipeline_version`，变更需重锚定 |
| 成本结构 | 抽取 + 社区摘要，LLM 调用最贵 | 抽取一次，检索便宜 | 抽取 + 人工表画像；检索极便宜（毫秒级） |
| 擅长 | 全局主题总结（"这个领域有哪些流派"） | 低成本混合检索 | 带条件的数值选型、证据追溯、拒答 |
| 不擅长 | 需要精确条件与口径的数值比较 | 同 GraphRAG | 开放式主题总结（无社区摘要层） |
| 评测口径 | LLM 判优劣（comprehensiveness / diversity 等） | 同类 | 锚定率、引用回读、规则拦截率、拒答正确率（需金标） |

## 三、对象映射（如果要把两者接起来）

| GraphRAG / LightRAG | 本项目 | 说明 |
|---|---|---|
| entity | `Chemical` / `Feature` / `Bath` / `Method` | 它们的实体合并靠 LLM，我们的靠名称归一 + InChI（未解析就标 `unresolved`） |
| relationship | 谓词（16 个）+ `Claim` | 它们的边是自然语言描述，我们的边是可校验的结构化谓词 |
| community | 无直接对应 | 我们的 `KnowledgeUnit` 是"同口径证据聚合"，不是"主题聚类"，两者可并存 |
| community report | 无直接对应 | 本项目无摘要层，这是明确的功能缺口 |
| keywords（LightRAG） | `Indicator` / `Motif` 词表 | 它们的自由关键词 → 我们的封闭词（可控但覆盖面窄） |
| text unit（引用源） | `Block` / `TableCell` | 我们更细，且回读校验 |
| entity description | `Claim` 集合 | 它们把多篇结论并成一段描述，我们保留为可分离、可判冲突的多条断言 |

## 四、四个关键区别

**1. 条件与口径：它们没有，我们有。**
GraphRAG 与 LightRAG 抽出的关系没有"在什么条件下成立"。多篇文献关于同一分子的结论会被合并进同一实体描述，于是"PEG 在 200 ppm 抑制"与"PEG 在 20 ppm 无明显作用"变成同一段文字的两种说法。本项目用 `window` 与 `comparability_key` 把两条结论分开存放，比较前先验口径。

**2. 证据与等级：它们不分，我们分。**
它们的关系不区分"表格里数出来的"与"讨论段作者推测的"。本项目用 `tier` 与 `EvidenceLink` 区分，并在 T1 缺失时降级。这一条直接决定选型排序是否可解释。

**3. 引用粒度：它们到块，我们到单元格。**
它们的引用回答"这段话来自哪块文本"；本项目要求"这个数来自第 3 页表 1 第 6 行第 5 列，且引用字符串回读一致"。对数值类问答，块级引用无法核对数字是否串行。

**4. 写入 vs 读取：方向不同。**
它们优化"召回得全"；本项目优化"写入得可核"。因此本项目对不确定的处置是拒收或降级，而 RAG 框架的处置是"仍然召回，交给模型判断"。

## 五、三种组合方式

**方案 A：本项目作知识底座，RAG 框架作检索层。**
把 `Claim`/`Observation`/`KnowledgeUnit` 物化成实体与关系，交给 GraphRAG 或 LightRAG 检索；回答前用本项目约束做一遍过滤（口径、等级、缺失项）。代价：需要一层导出与字段旁挂（否则窗口与等级在导出时丢失）；收益：复用成熟检索与全局总结能力。

**方案 B：用它们的社区层补本项目的短板。**
本项目没有"主题总结"能力，GraphRAG 的社区摘要正好补上：对添加剂族、机理流派作层次化摘要，作为"背景介绍"类回答；但任何涉及数值与条件的结论仍必须回到 `KnowledgeUnit`。这是成本最低的互补。

**方案 C：用它们的实体合并补身份解析。**
LightRAG/GraphRAG 的实体合并（同义名归并）比本项目当前的名称归一宽松，可作为候选生成器：先由它们提出"这两个名称可能同一物"，再由本项目的 `Chemical` 校验（来源、InChI、SMILES 是否有外部依据）决定是否合并。方向必须是从"提案"到"校验"，不能反过来。

## 六、风险

| 用法 | 风险 |
|---|---|
| 直接用 RAG 框架的图回答选型 | 条件被抹平：把不同浓度、不同参比电极、不同面积基准的结果并在一起，输出"某添加剂最好"而无窗口；这正是本项目 51 条约束在防的事 |
| 用向量相似度决定"哪些证据可比" | 相似度与可比性无关：`5 mV(SCE)` 与 `3 mV(Ag/AgCl)` 文本高度相似但不可比 |
| 把本项目的 `window`/`tier` 导出后不旁挂 | 一旦丢失，下游无法恢复；导出必须保留附加层，或保留原记录 ID 供回查 |
| 用社区摘要当结论 | 摘要是对"该社区相关文本"的概括，不含证据等级与冲突裁决，不能作为选型依据 |

## 七、什么时候用哪个

| 问题类型 | 该走哪条 |
|---|---|
| "这个领域有哪些添加剂族、研究趋势如何" | GraphRAG 全局检索（本项目无此能力） |
| "PEG 在酸铜体系的作用机理是什么" | 本项目 `Claim` + `Mechanism` 链，必要时用 LightRAG 补召回 |
| "AR=5 盲孔、2 ASD 下推荐哪种整平剂" | 本项目（口径过滤 + KU 排序 + 缺失项输出），RAG 只能提供候选 |
| "这条结论出自哪篇哪页" | 本项目（锚点到单元格 + 引用回读） |
| "文献对某添加剂是否矛盾" | 本项目 `Conflict`；RAG 框架不做冲突检测 |

---

## 八、结论

1. 三者不在同一层：GraphRAG/LightRAG 是检索与索引框架，本项目是写入契约与校验层；
2. 本项目的 `window`、`comparability_key`、`tier`、单元格级锚点，是三者在结构上都没有的；
3. 三者可组合：本项目作底座、RAG 作召回与主题摘要、实体合并作候选；
4. 组合时必须守住一条：**可比性与证据等级在图侧先过滤，向量只负责找候选**，否则约束形同虚设。
