# 实体、关系与约束的含义（Schema v1.1 语义讲解）

> 配套文件：[实体关系与约束清单.md](实体关系与约束清单.md) 是"查表版"（字段、条数、落地位置）；本文是"读义版"，只解释每个对象代表现实世界里的什么、每条规则在防哪种错，不再重复字段清单。

## 一、总纲

这套 schema 只回答一个问题：**一条文献事实，要满足什么形态，才配被取出来用于添加剂选型和化学问答。**

它把三件事分开：

- 「文献说了什么」——Observation / Block（原文层）
- 「我们据此断言了什么」——Claim（论断层，带谓词、窗口、极性、等级）
- 「这些断言在什么条件下、以什么强度成立」——window / EvidenceLink / KnowledgeUnit（条件与强度层）

**实体是这三件事的载体，关系是它们之间的挂载方式，约束是"不许含混过去"的判决。**

## 二、实体：每个对象代表什么

### L0 锚点层：证明「这句话真在原文里」

- **Document** 是一篇文献本身，也是所有事实的最终归属。它带 `pipeline_version`，因为上游解析（清洗、公式归一、合并阈值）一改，位置哈希就变，旧锚点会静默错位——所以版本变化必须触发重锚定报告，而不是假装没事。
- **Block** 是文献里一段可定位的文字、标题、公式、图区或表区，用"页码 + 矩形 + 类型 + 切分序号"生成 ID。它代表**一切回读的最小单位**。带 `merged_from`、`split`、`part` 是刻意的诚实：被合并或被切开的段落，引用时不能声称"原文此处就是这段起止"。
- **Table / Figure / Equation / BibEntry** 分别是表、图、公式、参考文献条目。四者共享一个含义：**它们是证据的容器，不是结论**。图只登记"存在 + 图注 + 被谁引用"（曲线像素反推数值明确出界）；表的价值在单元格——只有到 `(table_id,row,col)` 才能核对"这个数是不是串行了"；公式是 TP 这类指标的合法性来源。
- 这套锚点层的意思很直白：**没有可回读位置的句子，在图里不存在。**

### L1 观测层：文献报告的「一个结果」

- **Observation** 代表一次测量或一次定性判定：一个值、一个范畴（void-free / superfill）、一个方向（升高/降低）。它是**数值的唯一落点**，并强制伴随指标、方法、参比电极、面积基准。
- 之所以独立于 Claim，是为了守住一条线：文献的原话属于文献，我们的论断属于我们；两者混在一起，后续就无法区分"作者说的"和"我们推的"。

### L2 事件层：结果是在什么条件下得到的

- **Experiment** 是一组共享装置、浴液基线和流程的实验系列。它存在的理由来自实测：一篇文献有 10–40 个条件组合，若按"表格一行 = 一个实验"建节点，事件会爆炸且语义重复。它同时声明"这一系列扫了哪些轴"（`swept_params`），把"温度既是条件又是变量"这类重复建模消掉。
- **Run** 是一次具体条件组合（表格一行）。它是**条件与结果绑定在一起的最小单元**，也是"不许把不同 Run 的条件拼到一条结论上"的执法对象。没有任何 reported 参数的空 Run 不被允许存在——它无法参与窗口求交，只是噪声。
- **AdditiveUsage** 是"某个化学物，在这次实验里，以什么角色、什么浓度被使用"。这是全图最关键的一次语义拆分：**角色不是分子的属性，而是分子在某工况下的用法**。PEG 在酸铜体系是抑制剂，换个体系可能不是；把角色挂到 Chemical 上，选型问题从根上就错了。选型真正的候选对象是 AdditiveUsage，不是 Chemical。

### L3 概念层：可以跨篇说话的东西

- **Chemical** 是物质身份，canonical 以 InChIKey 为准（异构体同键、盐型不同键）。未解析的物质保留为 `chem:unresolved:*` 的**一等公民**——没有 SMILES 不等于可以丢，只等于不能拿它做结构推理。SMILES/InChIKey 非空必须对应可查来源（PubChem / CAS / 作者给出），因为"按名字猜结构"会让下游预测输出看似合理的错数，且事后查不出。
- **Motif** 是结构基元（巯基、季铵、聚醚链、咪唑……）。它的意义是绕开分子长尾：语料里多数具体分子只有一篇证据，但"含季铵基的整平剂"可能有多篇支撑。词表里 20 条 SMARTS 全是 `draft`，因为还没在 48 篇的分子集上用 RDKit 验证过——这条状态如实反映了"结构类比检索"尚未落地。
- **BathClass / Bath** 是体系类别（枚举）与具体镀液（篇内编号，跨篇不合并）。前者是化学相容性检查的坐标（酸/碱/氰化物/CMP 抛光液），后者是条件的具体容器。`cmp_slurry` 被显式标为域边界：非电镀，只能对照。
- **Feature** 是被镀结构（通孔、盲孔、沟槽、铜柱、RDE、铜箔……）。它的存在是为了让"整平能力"这句话有意义：脱开孔型、深宽比、孔径谈整平，等于没有信息。原文只写 via 时分不清通盲，就保留 `ambiguous=true`，不硬猜。
- **Parameter** 是受控实验变量注册表（15 个）。它代表窗口求交的"轴"。未登记参数意味着两把不同的尺子，所以必须拒收而不是宽容收下。
- **Indicator** 是被测量的指标（37 条，四族）。四族的差别本身就是含义：`filling_behavior` 才能支撑选型结论，`film_performance` 只能支撑镀层性能（硬度提升 ≠ 整平提升），`method_derived` 只能作机理证据（DFT 计算的量不是工艺实测值），`composition_structure` 是成分/晶粒。**跨族推理是这批语料最容易犯的实质错误**，指标注册表就是为此存在。
- **Method / Role / Mechanism** 三个枚举各代表一维语义：方法是"用什么手段测的"（也是冲突归因的一维：同论断不同方法不算真矛盾）；角色是"功能定位"（可变，且允许 unknown）；机理是"解释链的节点"（必须能接回具体观测，否则"为什么"只能靠模型现场编）。

### L4 知识层：我们自己的结论

- **Claim** 是一条结构化论断：谁、以什么谓词、对什么、在什么窗口内、什么极性（断言/否定/无效应/条件性）、什么证据等级。它是**可校验、可判冲突的最小知识单元**。它不携带锚点本身——锚点挂在 EvidenceLink 上，这是把"结论"和"证据强度"剥开的关键设计。
- **EvidenceLink** 是一条论断与一处证据之间的支撑关系：支持/反驳/部分支持/无信息，加等级和锚点回读结果。它让"降级"有据可查——不是我们不喜欢这条结论，而是它的证据形态只到 T2。
- **Conflict** 是两条以上在同一口径下不一致的记录，外加裁决。它代表一种态度：**矛盾不藏进同一段描述，也不靠取平均抹平**；必须说清是条件不同（`window_explains`）、测量不同（`measurement_explains`），还是真的对立（`unresolved` / `abstain`）。跨口径的差异不算矛盾，那叫测量口径不同。
- **KnowledgeUnit** 是"同一口径下多条证据合起来到底支持什么"：有效窗口、支持类别（consensus / single_source / conflicting）、文档数、独立实验数、**缺哪些必需参数**。它是选型排序的落点，也是拒答的依据——`missing_params` 全库都没报道时，回答必须原样说出来，而不是给出一个听起来完整的推荐。

## 三、关系：每条边断言了什么

### 3.1 结构边（7 条）——「东西在哪、谁提到谁」

`HAS_BLOCK` / `HAS_TABLE` / `HAS_FIGURE` / `HAS_EQUATION` 表示文献包含这些锚点，是覆盖率门禁的载体；`NEXT` 是阅读顺序（取上下文用，同页同栏才连）；`CITES` 是参考文献引用（目前依赖 enrich 重跑，暂不可用）；`REFERS_TO` 是正文提到某图/表/式——它回答"这个结论在正文哪句被讨论"，与"数据在哪张表"是两件事。

### 3.2 事件边（10 条）——把条件和结果钉在一起

`HAS_RUN`（系列含哪些组合）、`USES`（这次组合用了哪些添加剂）、`OF_CHEMICAL`、`HAS_ROLE`（角色只能从这里生长）、`IN_BATH`、`ON_FEATURE`、`YIELDS`（结果落点）、`MEASURES`、`BY_METHOD`、`CONTROL_OF`（谁是空白/基液/商用品对照）。

这一串的含义是：**任何一条观测，都能沿边回溯到它唯一的条件组合**。`CONTROL_OF` 尤其重要，它把"对照"从读者推断变成图上事实。

### 3.3 概念边（11 条）——跨文献可比与可解释

| 边 | 含义 |
| --- | --- |
| `CONTAINS` | 镀液含某组分（带浓度） |
| `OF_CLASS` | 体系归类 |
| `HAS_MOTIF` | 分子含某基元，带证据来源（文本提及 / 子结构匹配 / 作者声明） |
| `ALIAS_OF` | 同义名合并 |
| `SIMILAR_TO` | 结构相似，带分数与方法，**只用于召回候选** |
| `DERIVED_FROM` | 新合成整平剂的谱系 |
| `OPERATES_BY` | 通过某机理起作用（带窗口） |
| `PRECEDES` | 机理链的先后，表达过程联系而**不是因果** |
| `EXPLAINS` | 机理能解释某观测/结论（带 strength 与 step_index） |
| `DEFINES` | 公式定义指标 |
| `IN_CLASS` | 孔型归类 |

其中两条的分寸最值得说：`HAS_MOTIF` 共享的是结构，不是效果——"都有季铵"只能召回候选，不能继承结论；`EXPLAINS` 的存在是为了堵住"为什么"变成模型自由发挥，机理必须落到具体观测上，还要说明在什么条件下成立。

### 3.4 知识边（6 条）——结论的支撑与聚合

`ABOUT`（这条论断在讲谁）、`SUPPORTED_BY`（论断 → 证据链接）、`EVIDENCE`（证据链接 → 观测/块/表）、`CONTRADICTS`（对称的直接对立）、`IN_CONFLICT`（参与哪次裁决）、`AGGREGATES`（KU 由哪些 claim 聚合，**单向**，聚合不回改写原始论断）。

### 3.5 16 个谓词：断言层能说的 16 种话

| 谓词 | 这句话的含义 |
| --- | --- |
| `has_role` | 在此实验里担任某角色（角色随工况而变） |
| `affects_indicator` | 影响某指标，带方向与幅度 |
| `improves` / `degrades` | 方向隐含的改善 / 恶化，必须带窗口 |
| `causes_defect` | 导致某类缺陷（缺陷类型取固定枚举） |
| `invalid_in` | 在某体系或某结构下失效 |
| `component_of` | 作为体系组分（主盐/酸/络合剂，不作选型候选） |
| `has_motif` | 结构属性，禁止带窗口 |
| `acts_by` | 通过某机理起作用 |
| `precedes` | 机理链的下一步 |
| `motif_improves` | 基元层提升指标，跨文献聚合才能给分 |
| `analogous_to` | 类比迁移，按 T3 使用 |
| `derived_from` | 谱系来源 |
| `defined_by` | 指标由公式定义 |
| `supersedes` | 取代前代体系（工艺代际） |
| `reported_in` | 报道于某文献，仅用于"首次报道"类断言 |

**为什么封死 16 个、禁反向表达、`direction` 只许四个值**：语料一放大，"同义 / 逆向 / 粒度不同"三种漂移会各长出一串谓词，最后 Cypher 查询和窗口求交的语义会彻底崩塌。没有 `increases_eta`，只有 `affects_indicator(direction=increase)`——一个谓词一个语义，查询才能稳定。

## 四、约束：每条在防哪种错

### A 锚点（C-ANCHOR-01~04）——防「看起来有出处其实没有」

`quote` 必须与原文子串匹配，因为 LLM 复述式引用是幻觉的主要形态，而这是最便宜有效的过滤器；`block_id` 必须真实存在，否则溯源链已断；表格数值必须锚到单元格，只锚整表等于放弃错行检测。

### B 表格（C-TABLE-01~06、C-ANCHOR-05）——防「从读不懂的表里抽数」

ANOVA 表只能产统计支撑（显著性不是工艺值）；`unreadable` 表禁数值（从不可读位图抽数就是编数）；partial/位图 OCR 的数值最高 T2（溯源到原页也对不出字符）；维度必须与 CSV 和块元数据三方一致，这是"条件与结果串行"最早的预警；表—块—CSV 三向能反查，防同页多表按页码猜错位。

### C 化学（C-CHEM-01~05）——防「类型合法但化学荒谬」

禁猜结构；只在酸性体系报道过的添加剂出现在碱性体系必须标记；Cu↔Co 外推只能算类比（语料里没有任何一篇做对照）；酸铜体系缺主盐/酸/Cl⁻ 要标 `incomplete_bath`；主盐、酸、络合剂不得作为选型候选返回——把 CuSO₄ 当抑制剂是典型错抽。

### D 单位（C-UNIT-01~04、C-PARAM-01）——防「两把尺子比大小」

数值无单位即废数据；ppm↔mg/L、wt%↔mg/L 这类换算必须留前提（密度谁给的）；有电流密度却不声明波形的 Run 会污染窗口求交；同一窗口浓度必须同基准（质量/摩尔），跨基准求交是最易出错处；未登记参数会让求交拿两把尺子。

### E 指标（C-IND-01~05）——防「证据用错族」

Δη 脱离参比电极就是不可比的数；填充类结论缺孔型/AR/方法就只是话；TP 不绑定义式无法解释表里的值；跨族推理直接拒收；ΔE / Δη / dE / η 这类同形异义符号必须消解到具体指标，否则一个字母能骗过整条管线。

### F 证据分级（C-EV-01~06）——防「把定性当定量、把模型自评当证据」

T1 分两支：有数值的一支要求数值+单位+≥2 个条件参数+可回读锚点；只有明确措辞的一支（角色、机理、组成、结构属性）允许凭原文显式措辞入 T1。条件参数按 `own ∪ inherited` 计（否则表格通道几乎全灭）；继承来的条件必须有 `run_ref` 且 Run 里真有——凭空补条件是"最隐蔽的一类幻觉"；T2 不许携带数值；冲突必须写裁决说明；`confidence` 不得抬等级；无锚点断言归零。

### G 角色与事件（C-ROLE-01/02、C-EXP-01/02）——防「角色挂错地方」和「空条件事件」

角色只能在 AdditiveUsage 上；`role_source=unknown` 就必须写 `unknown`（防"原文没说但模型觉得像抑制剂"）；Run 至少一个 reported 参数；声明扫了某轴，各 Run 就该有 ≥2 个取值，否则是 ETL 把列读错了。

### H 窗口（C-WIN-01~03）——防「把未知当满足」

区间上下界必须成立（反了会静默返回空，误报"文献未涵盖"）；`not_reported` 计 UNKNOWN、不得算满足，只有原文明确"不限"才是开区间——这是给出**假文献支持**的直接原因；同一参数单位先归一到 canonical，否则 mA/cm² 与 A/dm² 差 10 倍。

### I 元数据（C-META-01~03）——防「无法复现、来路不明」

抽取模型 / prompt 版本 / 日期三要素（换 prompt 要能对比）；枚举封闭（抑制同义爆炸）；`doc_id` 必须在 48 篇清单内（防付费墙或无关文献混入）。

### J 谓词（C-PRED-01/02）——防「谓词漂移摧毁查询」

未登记谓词不是拒收而是进待审区（warn + pending），留给人工决定合并还是新增；但签名和窗口义务是硬拒——不校验签名等于退回开放三元组，注册表就白建了。

### K 可比性（C-CMP-01~03）——防「不同口径混排」

比较、排序、检出冲突、聚合之前 key 必须同且可算；同 key 只是初筛必要条件，关键口径仍缺失就是 UNKNOWN；口径差异造成的不一致必须标 `measurement_mismatch`，不能当"文献互相矛盾"；排序只许偏序（tier → 支持类别 → 文献/实验数 → 年份），**禁止自造加权分**——没有标定的权重会让排序看起来科学、实则不可解释。

### L 聚合（C-KU-01~03）——防三种聚合病

单篇结论包装成共识（consensus 必须 ≥2 篇或 ≥3 个独立实验）；用未知撑大窗口（effective_window 只由 reported 求交，空交集记 null，原窗口照旧有效）；证据等级靠数量叠加（KU 的 tier = 最强单条，不许"多篇 T2 相加变 T1"）。

### M 解释链（C-EXPLAIN-01）——防「机理随便套用」

EXPLAINS 必须带窗口或显式"不限"，强度只取 strong / partial / speculative——机理在什么条件下成立比机理本身更关键。

## 五、三条贯穿全篇的原则

1. **未知 ≠ 不限。** `presence` 三态（reported / not_reported / unconstrained）贯穿窗口、排序、冲突、聚合。把缺失当开区间，就是把"文献没说"包装成"文献支持"。
2. **能拒就拒，不能拒就降级，绝不猜着进图。** 51 条约束的处置只有三档；降级不是丢弃，而是把"这条结论只值 T2"写在数据里，让下游知道分寸。
3. **口径和证据先在图侧过滤，检索只负责找候选。** `comparability_key`、`tier`、`window` 一旦在召回阶段被抹平，后面再有约束也救不回来——这也是为什么这层契约必须先于任何 RAG 框架落地。

## 六、这套设计不做什么（对照 GraphRAG / LightRAG）

| 不做 | 含义 |
| --- | --- |
| 不做社区检测与社区摘要 | 没有"这个领域有哪些流派"式的全局主题总结能力；`KnowledgeUnit` 是同口径证据聚合，不是主题聚类 |
| 不做实体/关系的自由文本描述 | 关系是 16 个受控谓词，不是 LLM 生成的自然语言描述；实体无 description 字段 |
| 不做关键词抽取与向量索引 | 关键词层是封闭词表，schema 内无 embedding/vector 字段；向量若要接，只能是图外可重建索引，靠记录 ID 回查 |
| 不做检索执行 | 契约只定义"什么算可比、什么算有证据、什么必须拒答"，不含索引、遍历、排序执行与答案生成 |

这三不做的代价是缺主题总结与低成本召回；换来的是**条件、口径、证据等级不会被召回阶段抹平**——这正是这批文献最容易出事的地方。
