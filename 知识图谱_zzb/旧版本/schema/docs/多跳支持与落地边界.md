# 多跳支持与落地边界

2026-10-19，依据本地 Schema v1.1 与现有脚本。这里评估结构和程序现状，没有运行真实多跳问答，也没有新增图谱事实。

## 结论

现有节点与边足以表达常见的跨实验、跨文献和机理证据多跳路径，无须为“多跳”另造一套基础模型。当前交付仍是契约与校验器，未包含真实图谱、查询执行器或多跳质量评测。

## 可表达的查询

下表箭头严格沿用 schema 的边方向；`←` 表示查询需要反向查入边，并非要求存一条反向边。路径都是结构示意。

| 问题 | 结构路径 | 使用条件 |
| --- | --- | --- |
| 某添加剂在什么实验中得到什么结果？ | Chemical ←OF_CHEMICAL— AdditiveUsage ←USES— Run —YIELDS→ Observation —MEASURES→ Indicator | 用同一个 Run 的 IN_BATH、ON_FEATURE 和 conditions 筛工况，禁止把不同 Run 拼在一起 |
| 为什么会影响某指标？ | Chemical/Motif —OPERATES_BY→ Mechanism —PRECEDES→ Mechanism —EXPLAINS→ Observation/Claim | PRECEDES 表达过程联系，不能仅因路径连通就断言因果；各步须核对窗口、支撑论断与原文 |
| 一条汇总结论的文献依据是什么？ | KnowledgeUnit —AGGREGATES→ Claim —SUPPORTED_BY→ EvidenceLink —EVIDENCE→ Block/Table/Observation | 落到 Observation 后继续读 measured_at；来源对象再用 doc_id/anchors 回读文献、页码或单元格 |
| 不同论文里哪些添加剂有共同基元？ | Chemical A —HAS_MOTIF→ Motif ←HAS_MOTIF— Chemical B | 跨篇依赖统一身份与基元登记；共享基元只能召回候选，不能继承效果 |
| 文献为何结论不一致？ | Claim A —IN_CONFLICT→ Conflict ←IN_CONFLICT— Claim B | 核对窗口、测量口径、resolution 与原始证据；无裁决时保留分歧 |

## 当前缺什么

1. **真实记录与稳定身份。** 先抽取、归一化并物化 claims/nodes/edges；有结构定义不代表有相应实例边。
2. **查询执行。** 实现实体链接、允许的路径模板、正反向邻接查询、深度与分支限制、去环；现有 scripts 负责校验，没有遍历或问题分解程序。
3. **每步证据绑定。** OPERATES_BY/PRECEDES 等概念边没有统一必填的 claim_ids/anchors 槽；执行侧必须建立每条推理边到支撑 Claim 的可复核映射，并在需要时补齐契约与校验。端点合法不等于每一步有证据。
4. **整条路径的语义检查。** 当前没有多跳路径级校验器；需逐步核对 Run 身份、窗口兼容、测量口径、review、证据等级与冲突，不能把单条记录通过校验等同于链式结论成立。跨文献推理不得提高任何步骤的证据强度；类比按 T3 使用。
5. **真实问题验收。** 用试点论文标注问题、预期路径和来源；覆盖正确召回、跨 Run 错拼、缺失条件、冲突和无证据拒答。现有人工夹具回归不能代替此项。

[retrieval_contract](../schema.yaml) 已定义 chunk 回查、表格回读、结果字段与证据资格；它尚未定义完整的多跳计划、路径结果和链路验收协议。

最直接的下一步：选 1–6 篇试点，先跑通“添加剂→Run→Observation”和“Claim→EvidenceLink→原文”两类路径，再接机理链及跨篇聚合；不需要为了这一点先更换整个 Schema。
