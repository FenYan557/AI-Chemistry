# 知识图谱主流结构综述与本项目选型说明

> 设计背景材料，保留当时的论证；当前契约与实现状态以 [README](../README.md) 和 [schema.yaml](../schema.yaml) 为准。本文的性能估计、框架比较及文献检索结论未在本次整理中重新验证，不能作为当前实测结果。可比性键仅作初筛，关键口径缺失不能证明可比。

本文分两部分：先综述知识图谱在学界与工业界实际被采用的几种结构及其代价，再逐条说明本项目为什么选择 `L0 锚点 / L1 观测 / L2 事件 / L3 概念 / L4 知识` 这一组合，以及在什么条件下应当推翻这个选择。

一句话结论：**最常见的结构（RDF 三元组 / 属性图）在"可溯源、可比对、能拒答"三条硬要求上不可用；本体驱动与事件中心能解决一部分；只有把"事件中心"与"声明-证据"叠在一起才能全部满足。本项目的结构就是这两者的组合，加上一层位置锚点与一层可比性约束。**

---

## 一、分析框架：结构由三部分组成

讨论"结构"时容易混在一起说，先拆成三个正交维度。这一拆分与 Hogan 等对知识图谱要素的划分（数据模型、模式、身份、上下文、溯源）方向一致[1]。

| 维度 | 问什么 | 取值 |
|---|---|---|
| **表示**（节点与边的形状） | 一条事实画成什么 | 三元组、属性图、n 元重ified、超图、事件、文档/块 |
| **组织**（模式从哪来） | 哪些类型与关系允许出现 | 上位本体驱动、领域本体驱动、模式先定、动态归纳、无模式 |
| **附加层**（正交能力） | 事实之外的元信息 | 溯源、声明-证据、时间、不确定性、可比性 |

同一份语料，表示选错会导致某些问题**在结构上无法回答**；组织选错会导致**同一含义出现多种写法**；附加层缺失会导致**结论无法核对**。三者要分别判断。

## 二、主流结构逐一讨论

### 2.1 RDF 三元组与属性图（最主流）

形态：`(主语, 谓词, 宾语)`，或带属性的节点与边。
代表：RDF/OWL 生态、Wikidata、Neo4j 属性图；系统综述见 Hogan 等[1]。
擅长：通用查询、模式灵活、工具链成熟、社区最大。
代价：**一条多元事实必须拆成多条三元组**，条件与出处只能靠重ification 或旁挂节点补；查询时需要多跳拼接，且拼错的查询不会报错只会少结果。
主流度：工业默认与人文学科、开放数据的事实标准。

### 2.2 本体驱动（上位本体 → 领域本体 → 应用本体）

形态：先用 OWL 定义类与公理，数据实例化后由推理机推出隐含关系。
代表：BFO/ISO 15926（工业）、OntoCAPE（化工过程工程，分 upper/middle/domain/application 四级）[2]、EMMO（材料多视角本体）[3]、PMDco 3.0（材料数字化的模块化核心本体）[4]、MSEO（材料科学与工程本体）[5]。
擅长：语义严格、可做一致性检查与子类推理、跨库互操作。
代价：建模成本极高；推理结果的解释性差；改一处公理可能牵连大量实例；需要 RDF/OWL 栈。
主流度：生物医学与制造业的事实标准，材料领域近年推进明显（PMDco、EMMO）。

### 2.3 事件中心与 n 元事实

形态：把"某次实验/某次测量/某条声明"建成节点，条件与参与方挂在节点上。
代表：PROV-O 的 Activity[6]；W3C 关于 n 元关系的说明[7]；EventKG；文档级事件抽取（DocEE）[8]；n 元知识表示学习综述[9]。
擅长：天然承载多元、带条件、带时间的事实；避免三元组拆分。
代价：事件类型体系要自己定义；同一事件的实例化容易过细（一条表格行一个事件）或过粗。
主流度：新闻事件、生物过程、工业过程建模中的主流做法；通用 KG 中的常见扩展。

### 2.4 超图与因子图

形态：一条超边连接任意多个节点；或把事实看作张量、用因子分解表示。
代表：超图神经网络、n 元关系学习（见[9] 所述方法族）。
擅长：高阶关系（4 元以上）表达自然。
代价：查询语言与工具链不成熟；可视化与人工检查困难；对"条件"这种带值对象的结构仍需额外设计。
主流度：方法研究活跃，工程落地少。

### 2.5 声明-证据与信念（claim + qualifier + provenance）

形态：把"某文献声称 X"作为一等对象，配限定符与出处，再由聚合规则合成可信度。
代表：Wikidata 的 statement 模型（claim + qualifiers + references）[10]；纳米出版物的三层结构（assertion / provenance / publication info）[11]；BEL[12]；INDRA（把语句装配成带 belief 分数的因果网络）[13]。
擅长：可信度、冲突、拒答；能回答"依据是什么、几条独立证据"。
代价：需要设计证据等级与聚合规则；聚合规则若无标定，排序不可解释。
主流度：生物医学知识库的事实标准；事实核查与科学论断抽取中常见。

### 2.6 表格/关系库式

形态：把表格按行列直接建成关系表或"表→实体"的映射图。
代表：Tab2Know（从论文表格建 KB，需预定义概念框架）[14]。
擅长：与实验表格天然对齐、ETL 直接、数值精度高。
代价：只能表达"表里有什么"，无法表达机理、冲突与跨表聚合；表结构不成体系时画像成本高。
主流度：材料与化学数据抽取的标准做法（配合属性抽取工具，如 ChemDataExtractor[15]）。

### 2.7 文档-块图与引用图

形态：文档、章节、段落为节点，引用/相似为边。
代表：S2ORC[16]、论文引用网络、RAG 中的 chunk 图。
擅长：建设成本最低，检索稳定，适合"哪里提到过"。
代价：不能回答"该选哪个"，只能定位；没有条件与证据等级。
主流度：学术检索与 RAG 系统的默认底座。

### 2.8 图 + 向量混合（GraphRAG 类）

形态：图用于结构化遍历，向量用于语义召回，二者融合。
代表：GraphRAG[17]、HippoRAG 等。
擅长：长文档、开放问题的召回；对措辞差异不敏感。
代价：相似度会绕过硬约束（把不同测量口径的证据排在一起）；可复现性依赖嵌入模型版本。
主流度：2024 年起检索侧的热点，工业界采用迅速。

### 2.9 参数化知识（隐式）

形态：不建显式图，知识留在语言模型参数里。
代表：LAMA 起的一系列评测[18]；材料领域大模型综述[19]。
擅长：零建模成本、表达流畅。
代价：不可溯源、不可审计、无法给出"第几页"；更新需重训或检索增强。
主流度：LLM 阵营的主流路线，与显式 KG 长期并存。

### 2.10 工作流/计算图（可执行知识）

形态：把规则或计算写成有向图（DAG），执行得到结论。
擅长：配方筛选、参数优化、可复现计算。
代价：不积累文献证据；规则变了历史结论无法追溯原因。
主流度：工艺工程与数据流水线中的标准做法，通常作为 KG 的执行侧组件。

## 三、主流度判断

| 结构 | 主流度 | 依据 |
|---|---|---|
| RDF / 属性图 | 工业默认 | 工具链与开放数据事实标准；Hogan 等综述[1] |
| 本体驱动 | 领域主流（生物医学、制造、材料） | PMDco[4]、EMMO[3]、MSEO[5]、OntoCAPE[2] |
| 事件中心 / n 元 | 领域主流（事件、过程、临床） | PROV[6]、DocEE[8]、n 元表示综述[9] |
| 声明-证据 / 信念 | 领域主流（生物医学） | 纳米出版物[11]、BEL[12]、INDRA[13] |
| 表格式 | 领域主流（材料/化学抽取） | Tab2Know[14]、ChemDataExtractor[15] |
| 文档-块图 | 工业默认（检索） | S2ORC[16] |
| 图+向量 | 兴起中，采用迅速 | GraphRAG[17] |
| 超图/因子图 | 研究活跃、落地少 | 见[9] |
| 参数化 | 另一条主线 | LAMA[18] |

没有"唯一的学界标准结构"。不同社群按任务选型，且近年趋势是**混合**（图中带溯源、图配向量、本体配抽取）。

## 四、把需求写成硬约束

本项目的下游是两个任务（添加剂选型、化学问答）加一条底线（不确定时必须说不知道）。落成六条硬要求：

| # | 要求 | 判定方式 |
|---|---|---|
| R1 | 每条结论能定位到页与表格单元格 | 锚点必须存在且引用文字回读命中 |
| R2 | 条件可表达，且"未报道"与"未限制"可区分 | 三态 `presence`；缺参数必须显式输出 |
| R3 | 只有同一测量口径的证据可比 | 六段 `comparability_key`；跨键禁止比较 |
| R4 | 证据强度可分级，聚合可解释 | T1–T4 + 支持度三档；禁止未标定加权分 |
| R5 | 规则可机器判定，能拦住错误而非只提醒 | 51 条约束，三档处置，退出码可见 |
| R6 | 规模适配 48 篇，人工可控 | 建模与校验成本须在 2 人周量级 |

## 五、淘汰过程：每种结构在 R1–R6 下如何失效

| 结构 | 失效点 | 具体后果 |
|---|---|---|
| RDF 三元组 / 属性图 | R2、R3、R4 | 一句"DB 在 1 ppm 时使填充变差"要拆成多条边，条件与出处旁挂；查询时把不同浓度、不同参比电极的结果并在一起比较，得到相反结论也无法察觉 |
| 纯本体驱动（OWL） | R6，部分 R3 | 用公理表达"两个观测可比"需要把测量口径建模成类与约束，工作量数倍于收益；且推理出的可比性无法给出人类可读的理由 |
| 超图 / 因子图 | R5、R6 | 缺少成熟的约束校验与可视检查工具；48 篇规模下不划算 |
| 表格式单用 | R1、R4 | 能抽数值，但得不到机理、冲突与跨表聚合；无法回答"为什么" |
| 文档-块图单用 | R2、R4 | 只能回答"哪篇提到过"，不能排序、不能分级 |
| 图 + 向量单用 | R3 | 相似度会把"SCE 下 5 mV"与"Ag/AgCl 下 3 mV"召回在一起；约束若不前移就形同虚设 |
| 参数化（纯 LLM） | R1、R4、R5 | 无法给出锚点，无法审计，规则无法执行 |
| 工作流 / 计算图 | R1 | 规则可执行但不积累证据，结论无法回溯到文献 |

淘汰不是否定这些结构本身，而是**它们各自缺少本项目必需的一到两项能力**，且缺口无法靠工程补丁解决（例如给三元组加旁挂节点，本质就是 2.3 与 2.5 的做法）。

## 六、选定结构

选定 = 事件中心（2.3）+ 声明-证据（2.5）+ 位置锚点 + 可比性约束。对应关系：

| 本项目 | 对应主流结构 | 承担哪条要求 |
|---|---|---|
| L0 锚点（Document / Block / Table / Figure / Equation） | 文档-块图（2.7）+ PROV 的 entity | R1 |
| L1 观测（Observation） | 测量/观测模型，属性值对象化 | R2、R3 |
| L2 事件（Experiment → Run → AdditiveUsage） | 事件中心（2.3）、PROV 的 activity | R2 |
| L3 概念（Chemical / Motif / Indicator / Method / Mechanism / Role / Bath / Feature） | 领域本体（2.2），但只取类与枚举，不做公理推理 | 组织维度：防止同义漂移 |
| L4 知识（Claim / EvidenceLink / Conflict / KnowledgeUnit） | 声明-证据（2.5） | R4、R5 |
| 两个正交附加：证据分级、可比性键 | 分别对应 2.5 与计量学可比性 | R3、R4 |

三个自建部分（不在主流结构里现成可得）：

1. **可比性键六段式**：把计量学的"可比"落到工程编码；
2. **`presence` 三态**：把"未报道"从"不限制"里分离；
3. **位置哈希锚点**：使块 ID 在清洗规则变动时仍指向同一位置。

---

## 七、与主流方案的兼容性（避免成为孤岛）

- 可导出为 RDF：节点即资源，边即三元组，`anchors` 落为 PROV 的 `wasDerivedFrom`；
- 术语可对齐 EMMO / PMDco / ChEBI，便于跨库互操作；
- 51 条约束可转写为 SHACL 形状（当前实现为 Python，语义等价）；
- 检索侧可叠加 GraphRAG，但**可比性与证据等级必须在图侧先过滤**，向量只负责找候选。

---

## 八、什么情况下应当推翻这个选择

结构不是永久决定，下列任一条件成立就应重新评估：

1. 出现稳定需要 4 元以上关系的查询（配方族、多组分交互）→ 考虑超图或因子图；
2. 需要一致性检查与子类推断（如同义分子归并后的矛盾检测）→ 转 OWL 片段 + 推理机；
3. 语料扩到数千篇、实体消歧成为主矛盾 → 引入更强的实体链接与向量召回，锚点层可能下沉到 chunk；
4. 开始要求"因果"而非"相关" → 现有结构不够，需要实验设计元数据（随机化、对照、重复）；
5. 要求给出数值置信区间而非等级 → 用 belief 分数（INDRA 式）替换 T1–T4；
6. 出现必须在线更新的需求（每日新增文献）→ 位置哈希与全量复跑的成本需重新核算。

---

## 九、结论

1. 知识图谱没有唯一标准结构，主流是"按任务选型 + 混合"；
2. 本项目的三条硬要求（可溯源、可比、能拒答）逐条排除了最常见结构；
3. 选定结构是事件中心与声明-证据的叠加，加上三个自建部件；
4. 该选择可通过导出 RDF、术语对齐、约束转 SHACL 保持与主流生态的互操作；
5. 结构可被推翻，触发条件已列明。
