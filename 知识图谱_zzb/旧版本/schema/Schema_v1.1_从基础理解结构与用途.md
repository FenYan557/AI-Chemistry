# 电镀添加剂知识图谱 Schema v1.1：从基础理解结构、抽取内容与用途

> 历史参考状态（2026-10-19）：用户已决定从头重建；本文的“当前”和“真源”仅指旧版 v1.1，不是新方案的约束。请先读[讨论总结](../../讨论/讨论总结_过程与最终结果.md)。

本文介绍当前项目中的电镀添加剂选型知识图谱结构，依据为同目录 `schema.yaml` 的 `meta.version: v1.1`，阅读日期为 2026 年 10 月 19 日。配套参考了 `claims.schema.json`、`constraints.yaml` 和 `lexicon/` 中的词表。

当前结构尚未冻结。版本以 schema.yaml 的 meta.version 为准，目录与实现状态见 README。本文讲解已经定义的数据组织方式；结构允许表达一种信息，并不代表这种信息已经从文献中抽取完成。

## 一、Schema 是什么，这个项目为什么需要它

Schema 是对数据结构的明确规定，主要回答以下问题：

- 系统记录哪些对象，例如化学物质、镀液、实验条件、测量结果。
- 每种对象记录哪些字段，例如化学名称、浓度、单位和来源页码。
- 哪些对象可以建立关系，以及关系的方向和含义。
- 哪些信息必填，哪些信息允许缺失，遇到缺失时如何处理。
- 哪些记录可以用于定量比较，哪些只能用于定性说明。

电镀论文中的一个结论通常同时涉及添加剂、基础镀液、添加浓度、电流条件、基体结构、测试方法和结果。只记录“某添加剂改善填充”会丢失其成立条件，也无法说明结论来自哪项实验。

这个 Schema 的目标，是让系统能够完整表达这样的信息：

> 文献中的某个实验系列，在某次具体条件组合下使用了某种添加剂，通过某种方法得到某个结果；作者或抽取系统据此形成一个带适用条件的论断，论断可以回查原文。

后续再根据这些记录，回答“哪些添加剂值得考虑”“适用于什么条件”“证据来自哪里”“不同论文的结论是否可以比较”等问题。

Schema 本身只定义规则。读取论文、抽取记录、计算派生字段、建立检索索引和生成回答，都需要另外的执行程序。

## 二、先理解几个基本概念

### 1. 实体、实体类型与节点

实体是系统需要区分和记录的具体对象，例如某一种化学物质、某一篇论文或某一次实验条件组合。

实体类型规定这类对象的共同结构。例如 `Chemical` 是“化学物质”类型，具体论文中出现的不同化学物质是该类型的不同记录。

在图数据中，一条对象记录通常表现为一个节点。节点具有唯一标识符 `id`、类型 `type`，以及名称、来源等属性。

当前文件登记了 **24 类节点或注册对象**。这里需要稍作区分：`Parameter` 明确作为参数注册表使用，不要求单独生成图节点；`Role` 等对象也主要由固定枚举定义。因此，“24 类”表示结构中登记的对象类型数，并不意味着每类都必须从论文中抽取出独立节点实例。

### 2. 属性

属性描述一个对象自身的信息。例如：

- `Chemical.name_canonical`：化学物质的规范名称。
- `Run.conditions`：该次实验的具体条件。
- `Observation.value`：测量结果的数值和单位。
- `Document.year`：文献发表年份。

不是每个概念都必须成为独立节点。例如某次实验的温度通常作为条件属性保存，不需要为每个温度值建立一个独立节点。

### 3. 关系与边

关系描述两个对象之间的联系。在图数据中，关系以边表示，包含起点、关系类型和终点。

例如：

```text
Experiment --HAS_RUN--> Run
Run --YIELDS--> Observation
Observation --MEASURES--> Indicator
```

含义依次为：实验系列包含某次条件组合；该次实验产生观测结果；该结果对应某个测量指标。

关系可以携带补充属性。例如镀液 `Bath` 与化学物质 `Chemical` 之间的 `CONTAINS` 关系，可以附带组分浓度。

### 4. 论断与谓词

论断 `Claim` 是一条明确的结构化陈述，基本形式为“主语—谓词—宾语”。

例如“添加剂 A 影响填充率”中，主语是添加剂 A，谓词是 `affects_indicator`，宾语是填充率指标。方向、实验条件、证据和审核状态另外记录。

**图边与论断谓词分属两个层面。** 图边组织对象之间的连接；论断谓词规定一条陈述的语义。当前有 34 类图边、16 个论断谓词，它们不是两套可以直接互换的名称。

### 5. 来源锚点

锚点 `anchor` 记录信息在原始材料中的具体位置，例如文献编号、页码、文本块编号，或者表格编号和单元格行列坐标，同时保存原文片段 `quote`。

锚点用于回答“这条记录具体来自哪里”。它只能支持来源核对，不能单独证明抽取的理解正确，也不能证明论文结论本身正确。

## 三、整体结构：五个层次分别记录什么

五层是解释数据职责的方式，不要求在图中额外保存一个“层号”字段。

| 层次 | 内容 | 主要解决的问题 |
| --- | --- | --- |
| L0 来源与定位 | 文献、文本块、表、图、公式、参考文献条目 | 信息来自哪里，如何回查 |
| L1 观测 | 数值结果或定性结果 | 原文报告了什么结果 |
| L2 实验事件 | 实验系列、具体条件组合、添加剂使用记录 | 结果是在什么实验中得到的 |
| L3 领域概念 | 化学物质、镀液、结构基元、指标、方法、角色等 | 实验涉及哪些对象与概念 |
| L4 知识表达 | 论断、证据关联、冲突、多证据聚合 | 可以形成什么结论，支持程度如何 |

可以按以下顺序理解一条记录：先找到原文位置，再记录实验和结果，再形成有证据的论断，最后决定是否适合与其他论断共同使用。

## 四、24 类对象：具体抽取哪些实体和信息

### 1. L0：保留文献来源与定位信息

| 类型 | 中文含义 | 主要字段或内容 |
| --- | --- | --- |
| `Document` | 文献 | 标题、DOI、年份、文献类型、关注金属、清洗版本和清洗诊断 |
| `Block` | 文档内容块 | 页码、页面位置 `bbox`、章节、文本或块类型、清洗合并及切分信息 |
| `Table` | 表格 | 表注、行列数、表头、CSV 路径、表格用途分类、OCR 状态 |
| `Figure` | 图片或图表 | 图号、图注、图片路径、图类型、图注配对信息 |
| `Equation` | 公式 | 公式正文、原始 LaTeX、原文编号、对应内容块 |
| `BibEntry` | 参考文献条目 | 参考文献序号、原文文本、可解析的 DOI |

`Block` 与 `Table` 可以同时记录同一张表的不同方面：Block 负责其在文档中的位置及清洗来源，Table 负责表格的矩阵结构和数值抽取规则。两者需要通过对应字段关联一致。

图像也需要登记，但当前设计不从数据图的像素直接读取精确数值。视觉模型生成的图像说明属于低置信信息，不能直接取得与可靠表格数值相同的证据地位。

`Equation` 的用途之一，是保留指标的定义。不同论文即使使用相同缩写，也可能采用不同计算方式，因此只记录缩写不足以判断结果能否比较。

### 2. L1：观测结果 Observation

`Observation` 记录原文报告的单个结果。它可以是：

- 一个数值或一个范围。
- 一个类别，例如有无空洞、沉积模式。
- 一个方向，例如增加、减少、无变化或非单调变化。
- 布尔结果或有序等级。

核心信息包括指标 `indicator`、结果类型 `outcome_kind`、数值与单位、测量方法 `method`、参比电极 `reference_electrode`、来源位置 `measured_at` 和可比性标识 `comparability_key`。

例如“填充率”是指标类型，“某次实验测得的填充率”才是一个 Observation。同一指标可以对应很多次观测。

文件中把 Observation 称为“数值的唯一落点”。更准确的理解是：**实验测量结果由 Observation 集中记录。** 温度、添加浓度、孔径等条件数值仍保存在相应对象和条件字段中；抽取阶段的断言格式也可能暂时携带数值。不能把这句话理解为整个数据结构只有 Observation 能出现数字。

### 3. L2：实验系列、条件组合与添加剂使用

| 类型 | 记录什么 | 与其他对象的区别 |
| --- | --- | --- |
| `Experiment` | 共享装置、基础镀液和流程的实验系列 | 表示一组具有共同实验背景的研究 |
| `Run` | 一次具体条件组合 | 表示该组研究中的某个具体实验条件 |
| `AdditiveUsage` | 某种物质在某次 Run 中的使用情况 | 保存浓度、角色、角色来源和添加顺序 |

一个 Experiment 可以包含多个 Run。实验系列声明考察了哪些变化参数 `swept_params`，每个 Run 再记录对应的具体取值。

对于已经确认属于结果矩阵的表格，一行通常可以对应一个 Run。配方表、统计表和描述表不能直接套用这一规则。

一个 Run 可以产生多个 Observation，例如同一次实验同时记录填充率、粗糙度和过电位变化。

AdditiveUsage 将“物质身份”和“本次使用情况”分开。例如系统可以知道某物质的化学身份，同时单独记录它在这一次实验中被作者称为什么角色、用了多少。

**角色依赖具体实验语境。** 当前设计不把“整平剂”或“抑制剂”作为某个分子在所有体系中的固定结论。若原文没有确定角色，允许记录 `unknown`。

基础组分还需要与待选添加剂区分。`is_component=true` 表示其按体系组分处理，不能直接作为添加剂选型候选返回。

### 4. L3：化学、工艺和测量概念

| 类型 | 中文含义 | 主要记录内容 |
| --- | --- | --- |
| `Chemical` | 化学物质或物种 | 原文名、规范名、别名、分子式、CAS、SMILES、InChIKey、身份解析状态 |
| `Motif` | 结构基元 | 分子中的局部结构类别，例如季铵、四唑、炔基、聚醚链 |
| `Bath` | 具体镀液实例 | 本篇文献中的镀液编号、金属、pH、体积及组分关系 |
| `BathClass` | 镀液体系类别 | 酸性硫酸铜、碱性镀铜、硫酸盐镀钴等受控类别 |
| `Feature` | 被研究的结构或电极形态 | 通孔、盲孔、沟槽等，以及孔径、孔深、深宽比、基底 |
| `Indicator` | 指标 | 填充率、粗糙度、吸附能等指标的名称、类别、单位及使用前提 |
| `Method` | 方法 | 实验表征、测量或计算方法的受控名称 |
| `Mechanism` | 机理 | 用于表达作用过程及解释关系的受控概念 |
| `Role` | 功能角色 | 加速剂、抑制剂、整平剂等角色，以及其他或未知 |
| `Parameter` | 工艺参数 | 浓度、温度、电流密度、波形等参数的注册定义 |

这里有几组区别需要特别注意。

**Chemical 与 Motif：** 前者是具体化学物质，后者是结构的一部分。同一分子可以包含多个基元，不同分子也可以具有相同基元。记录共同基元有助于检索结构相关的候选，但不能据此认定其工艺效果相同。

**Bath 与 BathClass：** 前者是文献中的具体配方，后者是体系类别。两篇论文都研究酸性硫酸铜，并不意味着它们的基础镀液配方一致。当前 Bath 按篇内实例记录，不跨文献直接合并。

**Parameter 与 Indicator：** 前者主要描述实验输入条件，后者描述测量或分析对象。例如添加浓度是条件，填充率是结果指标。

**Feature 与材料名称：** Feature 还表达几何及测试形态。平板电极上的结果，不能仅因为金属相同就直接视为盲孔填充结果。

Chemical 的身份可以是 `resolved`、`partial` 或 `unresolved`。原文只给简称或商业名称时，应保留尚未解析的记录，不能自行补造分子结构。SMILES 和 InChIKey 非空时必须有允许的来源。

指标分为四类：

| 指标类别 | 示例 | 对结论的限制 |
| --- | --- | --- |
| `filling_behavior` 填充行为 | 填充率、抛镀能力 TP、空洞或接缝、沉积模式 | 需要结合指标定义、结构与测量方法解释 |
| `film_performance` 镀层性能 | 硬度、光泽、粗糙度、电阻率 | 性能改善不能直接证明填充改善 |
| `method_derived` 方法派生 | 吸附能、HOMO–LUMO 能隙、电荷转移电阻 | 不能单独替代工艺填充实测证据 |
| `composition_structure` 组成结构 | 成分比例、晶粒尺寸 | 不能直接推出填充能力 |

例如，TP 与填充率即使都用百分数表达，也不是同一指标。系统要求保留定义和方法信息，避免把不同含义的数值直接合并。

### 5. L4：论断、证据、冲突与聚合结果

| 类型 | 主要内容 | 用途 |
| --- | --- | --- |
| `Claim` | 主语、谓词、宾语、条件范围、肯定或否定、证据等级、审核状态 | 表达一条可定位和审核的陈述 |
| `EvidenceLink` | 支撑哪条论断、来自哪个观测或原文位置、支持立场、证据等级 | 明确证据与结论之间的对应关系 |
| `Conflict` | 涉及的论断、差异类型、条件差异、裁决和说明 | 解释结论为何不一致 |
| `KnowledgeUnit` | 聚合的论断、证据窗口、共同支持范围、文献数、独立 Run 数、支持类别 | 供检索和推荐使用的汇总知识 |

**Observation 与 Claim 的区别：** Observation 记录一个结果；Claim 说明这个结果支持怎样的陈述。某次 Run 得到一个填充率数值，并不自动证明该添加剂导致填充率提高；是否存在合适对照、其他条件是否改变，也需要判断。

**EvidenceLink 的作用：** 同一段原文可能支持某个较窄结论，却不足以支持更宽泛的结论。证据是否支持论断、支持程度如何，需要针对这一对应关系保存。

**Conflict 的作用：** 结果不同可能由浓度、镀液、方法或指标定义不同造成，也可能是真正未解决的矛盾。系统需要保存原因与裁决说明，不能直接对相反结论求平均。

**KnowledgeUnit 的作用：** 将同一对象、同一论断方向及同一比较口径下的证据组织起来。支持类别分为 `single_source`、`consensus` 和 `conflicting`。其中 `consensus` 是本项目按证据数量设置的内部标记，不等同于整个研究领域已经形成共识；其数量门槛为至少两篇文献，或者至少三个独立 Run。

## 五、34 类图边：对象之间具体如何连接

下面列出当前登记的全部图边。`1:N` 表示一个起点可以对应多个终点，`N:M` 表示两端均可对应多个对象。

### 1. 文档组织与引用关系：7 类

| 边类型 | 方向 | 含义 |
| --- | --- | --- |
| `HAS_BLOCK` | Document → Block | 文献包含内容块 |
| `HAS_TABLE` | Document → Table | 文献包含表格 |
| `HAS_FIGURE` | Document → Figure | 文献包含图片或图表 |
| `HAS_EQUATION` | Document → Equation | 文献包含公式 |
| `NEXT` | Block → Block | 同页同栏中的内容块阅读顺序 |
| `CITES` | Block → BibEntry | 内容块引用某条参考文献 |
| `REFERS_TO` | Block → Figure / Table / Equation | 正文提及某图、表或公式 |

### 2. 实验与观测关系：10 类

| 边类型 | 方向 | 含义 |
| --- | --- | --- |
| `HAS_RUN` | Experiment → Run | 实验系列包含具体条件组合 |
| `USES` | Run → AdditiveUsage | 本次实验包含某次物质使用记录 |
| `OF_CHEMICAL` | AdditiveUsage → Chemical | 使用记录对应哪种物质 |
| `HAS_ROLE` | AdditiveUsage → Role | 该使用记录中的功能角色 |
| `IN_BATH` | Run → Bath | 本次实验使用哪份镀液 |
| `ON_FEATURE` | Run → Feature | 本次实验对应哪种结构或电极 |
| `YIELDS` | Run → Observation | 本次实验产生哪些观测 |
| `MEASURES` | Observation → Indicator | 观测对应哪个指标 |
| `BY_METHOD` | Observation → Method | 观测使用什么方法 |
| `CONTROL_OF` | Run → Run | 前者作为后者的对照 |

### 3. 化学与解释关系：11 类

| 边类型 | 方向 | 含义 |
| --- | --- | --- |
| `CONTAINS` | Bath → Chemical | 镀液含有某种组分，可附浓度 |
| `OF_CLASS` | Bath → BathClass | 具体镀液所属体系类别 |
| `HAS_MOTIF` | Chemical → Motif | 化学物质包含某结构基元，需记录依据 |
| `ALIAS_OF` | Chemical → Chemical | 化学物质标识之间的别名关联 |
| `SIMILAR_TO` | Chemical → Chemical | 计算得到的结构相似关系，附方法与分值 |
| `DERIVED_FROM` | Chemical → Chemical | 文献支持的合成或结构来源关系 |
| `OPERATES_BY` | Chemical / Motif → Mechanism | 在特定条件下涉及某机理 |
| `PRECEDES` | Mechanism → Mechanism | 机理过程的先后联系 |
| `EXPLAINS` | Mechanism → Claim / Observation | 某机理解释某个论断或观测，附范围和解释强度 |
| `DEFINES` | Equation → Indicator | 某公式定义某指标 |
| `IN_CLASS` | Feature → 枚举类别 | 结构实例所属受控类别 |

### 4. 知识与证据关系：6 类

| 边类型 | 方向 | 含义 |
| --- | --- | --- |
| `ABOUT` | Claim → 相关领域对象 | 论断涉及哪些对象 |
| `SUPPORTED_BY` | Claim → EvidenceLink | 论断具有哪些证据关联记录 |
| `EVIDENCE` | EvidenceLink → Observation / Block / Table | 证据关联指向具体观测或来源对象 |
| `CONTRADICTS` | Claim ↔ Claim | 论断之间存在相互矛盾关系 |
| `IN_CONFLICT` | Claim → Conflict | 论断属于某个冲突记录 |
| `AGGREGATES` | KnowledgeUnit → Claim | 聚合知识包含哪些原始论断 |

部分精确位置通过属性中的 anchor 保存，例如表格单元格行列坐标。理解来源时需要同时查看图边和这些定位字段。

## 六、16 个论断谓词：系统允许说哪些类型的话

| 谓词 | 中文含义 | 典型主语 → 宾语 | 条件范围要求 |
| --- | --- | --- | --- |
| `has_role` | 在相关实验中担任某角色 | Chemical → Role | 可选，并尽量关联 Run |
| `affects_indicator` | 影响某指标 | Chemical / Motif → Indicator | 可选，但具体证据分级可能要求补充 |
| `improves` | 改善某指标 | Chemical / Motif → Indicator | 必需 |
| `degrades` | 恶化某指标 | Chemical / Motif → Indicator | 必需 |
| `causes_defect` | 导致某缺陷 | Chemical / Run → 缺陷类别 | 必需 |
| `invalid_in` | 在某体系或结构下失效 | Chemical → BathClass / Feature | 必需 |
| `component_of` | 作为镀液组分 | Chemical → Bath | 必需 |
| `has_motif` | 具有某结构基元 | Chemical → Motif | 不携带工艺条件范围 |
| `acts_by` | 通过某机理起作用 | Chemical / Motif → Mechanism | 可选 |
| `precedes` | 机理过程先于另一过程 | Mechanism → Mechanism | 可选 |
| `motif_improves` | 某类结构基元改善某指标 | Motif → Indicator | 可选 |
| `analogous_to` | 与另一物质或基元存在类比关联 | Chemical / Motif → Chemical / Motif | 可选 |
| `derived_from` | 来源于另一物质 | Chemical → Chemical | 不携带工艺条件范围 |
| `defined_by` | 指标由某公式定义 | Indicator → Equation | 不携带工艺条件范围 |
| `supersedes` | 取代前代物质或体系 | Chemical → Chemical | 可选 |
| `reported_in` | 报道于某文献 | Chemical / Motif → Document | 不携带工艺条件范围 |

谓词不是任意文本。未登记的表达先进入待审状态，再判断能否归入已有谓词或需要扩展。

方向也使用固定取值，例如 `increase`、`decrease`、`none`、`non_monotonic`。数值增加是否代表性能改善，需要结合指标含义判断：粗糙度增加和填充率增加的评价含义不同。

## 七、条件、数值与缺失值如何表达

### 1. 七种值对象

值对象是嵌入其他记录中的结构化字段，不一定独立生成节点。

| 值对象 | 用途 |
| --- | --- |
| `presence` | 区分原文已报道、未报道和明确不受限制 |
| `quantity` | 记录数值、区间、单位、原文写法和换算状态 |
| `param_value` | 在数值结构上增加参数名、所属对象和存在状态 |
| `window` | 组织一组与论断适用性相关的参数条件 |
| `anchor` | 保存原文位置和原文片段 |
| `cross_section_arg` | 保存从其他章节取得的参数及其来源 |
| `defect_kind` | 限定空洞、接缝、烧焦、粗糙、剥离等缺陷类别 |

`param_value.of` 用于说明参数属于谁。同一次实验包含多种物质时，只有“浓度”不足以区分记录，必须知道是添加剂 A、添加剂 B 还是其他组分的浓度。

### 2. 工艺条件范围 window

这里的 window 是一组适用条件，可能包括浓度、温度、电流密度和波形等，不仅是一个单独的浓度区间。

原文给出单点时保存单点，给出明确范围时保存范围；波形等分类条件保存枚举。只测了两个浓度点，不能自动认定两点之间的所有浓度都有效。

条件可以直接来自结论所在位置，也可以从所属 Run 的实验条件继承。继承必须保存来源 Run，并且该 Run 中确实存在对应的已报道参数。

### 3. 三种存在状态

| 状态 | 含义 | 查询时如何使用 |
| --- | --- | --- |
| `reported` | 原文给出了参数值或范围 | 按已报道内容匹配 |
| `not_reported` | 原文没有说明 | 作为未知，不能当作满足条件 |
| `unconstrained` | 原文明示该参数不受限制或不影响适用性 | 按明确的不限制处理 |

例如，论文没有报告温度，不能据此说它支持用户提出的任意温度。未报道与明确不限制具有不同含义。

单位也属于数据含义。可精确换算的单位应统一后比较；涉及质量浓度与摩尔浓度等转换时，需要相应前提，不能仅按数字大小处理。

## 八、证据等级与审核状态如何影响使用

### 1. 证据等级 T1—T4

| 等级 | 设计含义 | 使用注意 |
| --- | --- | --- |
| T1 | 符合相应要求的文献直接证据 | 仍需遵守条件范围和比较口径 |
| T2 | 文献定性证据，或数值、条件等不足后的降级结果 | 不作为完整的定量结论使用 |
| T3 | 模型外推或类比推断 | 需要显示推断性质与不确定性 |
| T4 | 常识或专家规则提示 | 不代表具体文献实验已经证明 |

配套约束对 T1 采用两条判定分支：

- **数值分支：** 要求数值、单位、足够的已报道条件、有效原文锚点，以及通过的引用核对结果。条件可以有可追溯的 Run 继承来源。
- **明确措辞分支：** 某些角色、组分或结构属性等陈述，可以依据作者明确措辞和核对通过的原文记录判断，不要求所有 T1 都包含测量数值。

此外还要受谓词的等级上限约束。例如 `acts_by` 当前最高 T2，`analogous_to` 最高 T3。因此，即使作者明确提出某机理，也不能忽略该谓词限制而直接登记为最高等级。

T4 虽然在枚举中保留，但当前文献断言输入仍强制要求锚点。因此，不能直接把“无文献来源的专家规则”按普通文献断言导入；这类规则的独立接入方式还需要执行侧明确。

`confidence` 是模型对抽取结果的自评，与证据等级不同。模型给出较高自评分，不能使一条缺条件或缺来源的记录升级。

### 2. 审核与异常处置

记录审核状态包括 `pending`、`pass`、`reject` 和 `downgrade`。待审或拒收记录不能作为已验证证据返回。

51 条约束按三类处置：

| 处置 | 含义 | 示例 |
| --- | --- | --- |
| `reject` 拒收 | 当前记录不符合入图要求 | 缺锚点、单位不合法、主宾语类型不匹配 |
| `downgrade` 降级 | 保留可用部分，降低证据等级或转为定性 | 电位类结果缺参比电极 |
| `warn` 警告 | 保留记录并提示具体问题 | 电流密度有值但波形未声明 |

这些规则能检查已抽取记录是否符合规定，不能证明没有漏抽，也不能自动排除所有科学解释错误。

## 九、不同文献的结果怎样比较与聚合

### 1. 可比性标识 comparability_key

当前标识由以下信息组合：

```text
指标 | 主要方法 | 参比电极 | 结构类型 | 深宽比分组 | 电流面积基准
```

其作用是先筛出可能适合比较的记录。不同标识的数值不能直接排序、合并或判为相互矛盾。

**标识相同只是必要条件。** 如果关键字段都缺失，多个记录可能得到相同的缺省值 `na`，但这仍然表示未知。深宽比分组相同，也需要继续检查具体几何结构和实际工况。

证据充分程度与工艺性能优劣也应分开。一篇论文来源更明确，并不意味着它研究的添加剂在目标工况下性能一定更好。

### 2. 逐条证据窗口与共同支持范围

KnowledgeUnit 同时保留两类信息：

- `evidence_windows`：每条原始论断自己的条件范围。
- `effective_window`：按规则计算的共同支持范围，允许为 `null`。

例如，作为纯结构示例，假定两条可靠证据分别只支持某参数在 `[1, 2]` 和 `[4, 5]` 的范围。这些是假设值，不是本项目实验数据。两者没有共同区间，不能合并为 `[1, 5]`，也不能宣称 `[2, 4]` 已有文献支持。共同范围为空，原有两个证据范围仍然需要保留。

聚合还记录文献数量、独立 Run 数和缺失参数。多条较弱证据不会仅因为数量增加就自动升级成更高等级。

### 3. 排序与冲突

当前定义优先依据证据等级，其次考虑支持类别、文献数及独立 Run 数，年份作为后续区分因素。未裁决的冲突应单独展示，不能当作确定性推荐。

项目不使用未经标定的任意加权总分。对于比较口径不同、关键条件缺失或文献未覆盖的情形，应明确说明不能比较或证据不足。

## 十、从论文到问答：各阶段分别做什么

### 第一步：取得清洗后的文献内容

输入包括文献内容块、表格 CSV、元数据和用于检索的 chunks。根据当前结构记录的快照，语料范围为 48 篇文献、5316 个 blocks、5638 个 chunks 和 98 张表。这是清洗材料规模，不是已抽取实体数或知识论断数。

### 第二步：抽取篇内信息，输出 claims.jsonl

抽取器识别原文提到的物质、实验系列、Run、结果、条件和论断，保留原文名称 `name_raw` 与篇内实验编号 `experiment_local`、`run_local`。

JSONL 表示每行一个 JSON 记录，便于逐条处理。抽取期不要求模型决定化学实体、实验对象等最终统一标识；这些映射由归一化阶段处理。

### 第三步：校验断言，完成归一化

检查结构、枚举、单位、引用、条件和谓词要求。随后解析名称、统一单位、生成或映射图内标识，并保存无法确定的身份和缺失信息。

### 第四步：生成图记录

归一化结果形成 `nodes.jsonl` 和 `edges.jsonl`。例如，一份结果记录可以同时关联具体 Run、指标、方法和原始表格单元格。抽取输入中的原文来源和立场等信息，也需要在图中组织为对应的证据关联记录。

### 第五步：生成聚合知识

在条件、口径和证据允许时，组织 KnowledgeUnit，保留原始论断和证据范围。按 README 的当前说明，窗口聚合算法仍由下游执行侧实现，不能把结构字段已经存在理解为算法已经完成。

### 第六步：检索并回读证据

chunks 用于召回候选材料。命中后要依据 `source_block_ids` 和 `source_pages` 回读内容块；chunk 编号不能直接替代证据锚点。

如果召回的表格内容被截断，数值必须回读完整 CSV，并引用具体单元格。最后返回的结果还应包含条件、证据等级、审核状态、冲突和缺失参数。

GraphRAG 或 LightRAG 可以作为后续检索索引，但需要保留原记录标识并回查领域记录。当前检索适配器尚未实现。

## 十一、用一条简化记录理解结构如何配合

以下为教学示例，不对应本项目真实论文或实验结果：

> 某篇论文在一种具体酸性镀铜配方中，改变添加剂 A 的浓度，研究某种盲孔结构，并报告各条件下的填充率。

按照当前 Schema，可分步组织为：

1. 建立 `Document`，登记文献；建立对应 `Block` 和 `Table`，保存页码、正文和表格位置。
2. 建立 `Chemical` 保存添加剂 A 的身份。若只知道原文代号，保留未解析状态。
3. 建立 `Bath` 保存该文献的具体配方，通过 `OF_CLASS` 关联体系类别，通过 `CONTAINS` 关联组分。
4. 建立 `Feature` 保存盲孔类型和已报道的几何参数。
5. 建立 `Experiment`，说明这个实验系列变化的参数是添加剂浓度。
6. 对结果矩阵中确认属于不同条件组合的各行建立 `Run`。
7. 每次使用添加剂 A 的情况建立 `AdditiveUsage`，记录该次浓度与有依据的角色。
8. 每个填充率结果建立 `Observation`，关联填充率 `Indicator`、测量方法和表格单元格锚点。
9. 若原文与实验结果支持“添加剂 A 在某条件下改善填充率”，建立相应 `Claim` 和 `EvidenceLink`；是否能表达因果改善，还取决于对照及实验设计。
10. 有其他可用证据时，再判断是否适合建立或补充 `KnowledgeUnit`。

一条推荐因此可以说明：候选物质是什么，在哪种配方、结构和条件下有证据，测得了什么，证据如何核对，以及仍有哪些未知条件。

## 十二、这种结构的主要优点

### 1. 保留实验条件，减少无条件泛化

通过 Experiment、Run、AdditiveUsage 和 window，将物质效果与具体使用条件关联起来。对选型而言，可以优先查找与目标工况有关的记录。

### 2. 区分测量结果与解释结论

Observation、Claim 和 EvidenceLink 分开，使系统能够分别检查原始结果、论断含义和证据支撑关系。后续修改结论解释时，也能保留原始结果。

### 3. 能精确回查原文

页码、内容块、表格单元格和原文片段便于复核。出现错行、误解符号或来源变化时，可以定位到具体材料。

### 4. 明确限制比较与推理

指标分类、单位要求、比较口径和受控谓词能够减少将不同含义的数值混合使用。例如不会仅依据硬度提升就认定填充改善。

### 5. 可以保留未知与负面信息

未解析化学身份、未报道参数、失效条件、缺陷和冲突都有表达方式，不必为了生成完整回答而补造内容。

### 6. 同时支持选型和解释

条件与聚合知识用于筛选候选；Mechanism、EXPLAINS 和证据关联用于回答作用原因。解释仍需区分直接证据、定性结论和推断。

## 十三、主要缺点与使用局限

### 1. 建设成本较高

与只抽取名称和简单关系相比，这种结构需要正确识别实验系列、条件组合、组分、指标、方法和来源，还需要跨章节关联，归一化及复核工作更多。

### 2. 文献缺失信息会限制可用结论

结构要求保留的字段，原文未必提供。缺少波形、参比电极、面积基准或几何参数时，许多记录只能定性使用或标为未知。最终可定量比较的记录数量可能明显少于文献总量。

### 3. 多证据支持可能不足

若同一添加剂只见于少量论文，KnowledgeUnit 多数仍是单来源。设置聚合结构不能增加实际证据，也不能使同一来源的重复叙述成为独立验证。

### 4. 规则正确不代表抽取完整或科学判断正确

校验器擅长检查必填字段、单位和类型，但未必能识别所有实验归属错误、机制解释错误或遗漏。来源定位完整，也不等于语义抽取完整。

### 5. 领域扩展需要维护多个文件

新指标、新体系或新关系可能涉及主结构、词表、断言格式、约束和校验程序的同步修改。开放扩展能力受到限制，换取的是字段与关系的一致性。

### 6. 结构表达能力超过当前执行进度

当前目录以契约和校验程序为主，README 明确说明尚无真实抽取的图谱记录或检索适配器。多窗口聚合也尚未作为完整算法实现。

此外，酸碱相容、金属一致性、酸铜成分完整性三项化学约束仍待实现；结构基元的 SMARTS 仍为草案；部分表格尚需确定用途分类；引用与图表指代依赖的 enriched 数据还需要与新内容块同步。因此不能据当前 Schema 宣称上述能力已经全部运行。

### 7. 聚合标签和比较标识需要谨慎解读

内部 `consensus` 数量阈值不能替代对文献质量、实验独立性和适用范围的评价。comparability_key 也只能初筛，无法单独保证实验可比，更无法直接证明因果关系。

## 十四、它对这个项目的实际作用

| 使用场景 | 结构提供的支持 | 必须保留的限制 |
| --- | --- | --- |
| 添加剂初步筛选 | 按体系、结构、条件和角色查找候选 | 没有目标工况证据时需要明确说明 |
| 查询配方与用量 | 读取 Bath、AdditiveUsage 和 Run 条件 | 区分实测点、原文范围与未知条件 |
| 比较实验结果 | 核对指标、方法、单位与比较口径 | 信息不全时不能强行排名 |
| 解释添加剂作用 | 关联机理、观测、论断和原文 | 机理说明与性能实测分别评价 |
| 分析文献分歧 | 保存差异、冲突类型与裁决 | 未解决矛盾需要单独展示 |
| 规划后续实验 | 找出缺失参数、未覆盖条件和证据薄弱处 | 仍需单独设计并执行实验 |
| 生成可复核回答 | 返回结论、条件、来源和审核信息 | 回答的可靠性受原文与抽取质量限制 |

当前最直接的作用，是统一后续抽取、归一化、校验和问答所使用的数据含义。完成真实抽取与检索程序后，它可以支持依据文献条件和证据进行添加剂筛选；推荐是否有效，仍需要实际实验验证。
