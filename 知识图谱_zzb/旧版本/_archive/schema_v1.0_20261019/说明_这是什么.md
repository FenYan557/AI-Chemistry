# 说明：这个文件夹是什么，里面每样东西指什么

本文直接定义所有用到的名词，不使用类比。顺序是：基础概念 → 这套结构为什么这样拆 → 一个从真实表格到记录的完整例子 → 文件清单 → 当前状态。

读完应当能回答：
1. 这个文件夹属于整条数据处理的哪一步；
2. 里面每个文件的用途；
3. 一个术语（如 `Observation`、`tier`、`comparability_key`）各自指什么、定义在哪。

---

## 一、基础概念（先定义，后面全部基于这些）

| 名词 | 定义 |
|---|---|
| 知识图谱 | 由两类数据构成：**节点**（一条实体记录）与**边**（连接两个节点的关系记录）。查询时沿边遍历。 |
| 节点 | 一个 JSON 对象，含 `id`（该节点唯一编号）、`type`（节点类型名）和若干字段。 |
| 边 | 一个 JSON 对象，含 `from`（起点 id）、`type`（关系名）、`to`（终点 id）及可选限定字段。 |
| JSONL | 一种文本文件格式：每一行是一个独立的 JSON 对象。便于追加、逐行校验、流式读取。 |
| schema（模式） | 一份清单，规定"有哪些类型的节点与边、每类允许哪些字段、字段取值受什么限制"。 |
| 约束（constraint） | 一条可判定的规则，说明哪些取值组合不允许，以及不允许时如何处理。 |
| 词表（lexicon） | 允许取值的封闭枚举表。例如"指标"只能取 37 个已登记值之一。 |
| 校验器（validator） | 读取数据、按 schema 与约束逐条判定、输出问题的程序。 |
| 断言（claim record） | 抽取阶段产出的中间记录，一行一句"文献中的结论"。它不是节点，需经归一化才转成节点与边。 |

本文件夹只包含 schema、约束、词表、校验器，**不含任何节点、边或断言数据**。数据在生产侧生成，校验时再传入。

## 三、为什么不能直接把句子存成边

最省事的做法是：每读到"加 1 ppm 二嗪黑使填充变差"，就存一条边 `二嗪黑 →(使变差)→ 填充`。这个做法会在三处丢失信息，且丢失后无法补救：

1. **条件丢失**。同一篇文献里，二嗪黑在 1 ppm 时变差、在 5 ppm 时改善的现象很常见。若边上不带条件，"变差"这条边会覆盖"改善"那条，或两条边直接冲突而无法解释。
2. **出处丢失**。一条边若不记录来自哪篇文献的哪一页哪一表格单元格，事后无法核对。文献被审稿人质疑时，整条链无法自证。
3. **可信度丢失**。表格里数出来的值和作者在讨论段的推测，写成同一种边之后无法区分。检索时会把推测当数据用。

因此这套结构把一句话拆成三类记录，各自只承担一件事：

| 拆出的记录 | 只负责什么 | 对应上面丢失的信息 |
|---|---|---|
| `Run`（一次实验条件组合） | 记录条件 | 条件丢失 |
| `Observation`（一次测量） | 记录数值或定性结果，并记录测量方法 | 条件与方法的绑定 |
| `Claim` + `EvidenceLink`（结论 + 证据关系） | 记录"这句话"及其窗口、极性、可信度 | 可信度、出处 |

`EvidenceLink` 是单独的一类边，专门承载证据等级与锚点，因为同一句结论可能同时被一个 T1 数值和一个 T3 推测支撑，等级不能挂在结论上。

## 四、24 类节点（逐层说明各自记录什么）

按"离原文的距离"分五层。L0 直接对应 PDF 上的位置，往上每层都更抽象。

### L0：原文位置（6 类）

| 节点 | 记录什么 | 关键字段 |
|---|---|---|
| `Document` | 一篇文献 | `doc_id`、`doi`、`year`、`corpus_role`（综述/实验/学位论文）、`pipeline_version`、`cleaning_diagnostics`（该篇数值保留度） |
| `Block` | 页面上一段有确定位置的内容 | `block_type`、`page`、`bbox`（页内矩形坐标）、`section`、`text`；另有 `merged_from`（由几块合并）、`split`/`part`（是否被切分及序号） |
| `Table` | 一张表 | `table_id`、`etl_profile`（这张表能抽什么）、`evidence`（文本层还是位图 OCR）、`ocr_status`、`csv_path` |
| `Figure` | 一张图 | `kind`、`caption`、`caption_paired`（图注来自哪）、`no_number`（原文有无编号） |
| `Equation` | 一个公式 | `raw_latex`、`tag`（原文编号）、`defines`（定义了哪个指标） |
| `BibEntry` | 一条参考文献 | 序号、题名、DOI |

### L1：测量结果（1 类）

| 节点 | 记录什么 | 关键字段 |
|---|---|---|
| `Observation` | 一次测量得到的值或定性结果 | `indicator`（量的什么）、`outcome_kind`（numeric/qualitative/range）、`value`（数值对象）、`categorical_value`（定性或分类结果）、`method`、`reference_electrode`（电位类必需）、`measured_at`（锚点）、`comparability_key`（口径编码） |

**数值只存在 `Observation.value` 一处**。其他记录若需要该数值，引用 `Observation` 的 id，不复制数值。

### L2：实验条件（3 类）

| 节点 | 记录什么 | 关键字段 |
|---|---|---|
| `Experiment` | 共享同一套装置/浴液基线的实验系列 | `swept_params`（本系列变化了哪些参数） |
| `Run` | 一次条件组合（通常是表格的一行） | `conditions`（具体参数值列表）、`anchor` |
| `AdditiveUsage` | 某分子在某次 Run 中的用量与承担的功能 | `role`、`concentration`、`source`（文献中该分子身份是否解析成功） |

功能角色（整平剂/加速剂/抑制剂/氯离子…）只能记在 `AdditiveUsage` 上，不能记在 `Chemical` 上。同一分子在不同文献中角色可能不同，记在 `Chemical` 会导致冲突。

### L3：概念（8 类）

| 节点 | 记录什么 |
|---|---|
| `Chemical` | 具体分子或物种。身份未查证时保留原名称并把 `resolution_status` 记为 `unresolved`，不填猜测的 SMILES |
| `Motif` | 结构基元（季铵、四唑、炔基、聚醚链…），用于跨文献聚合 |
| `Bath` / `BathClass` | 具体镀液成分 / 镀液体系枚举（酸铜、碱铜、硫酸钴…） |
| `Feature` | 基体结构（通孔、盲孔、沟槽、铜柱、旋转电极）及尺寸参数（孔径、深宽比 AR） |
| `Indicator` | 测量指标，四项分类：填充行为 / 镀层性能 / 方法派生 / 组成与结构 |
| `Method` / `Mechanism` / `Role` / `Parameter` | 方法、机理、功能角色、工艺参数的注册枚举 |

### L4：知识（4 类）

| 节点 | 记录什么 | 关键字段 |
|---|---|---|
| `Claim` | 一句结论（同一个谓词、同一组条件范围） | `predicate`、`object`、`polarity`（断言/否定/无影响/条件性）、`window`、`evidence_tier` |
| `EvidenceLink`（以边或节点形式存在） | 结论与证据的支撑关系 | `tier`、`stance`（支持/反驳/中性）、`anchors` |
| `Conflict` | 两条以上结论互相不一致时的记录 | `claims`、`conflict_type`、`resolution`（未决/条件不同/测量不同/据此拒答） |
| `KnowledgeUnit` | 多篇证据汇总后的结论 | `effective_window`、`support_class`、`n_docs`、`n_independent_runs`、`missing_params` |

三个字段的含义需要单独说明：

- `window`：这组结论成立的参数范围。每条参数用 `presence` 三态之一标注——`reported`（文献报道了具体值）、`not_reported`（文献未提到）、`unconstrained`（作者声明不敏感或未控制）。**未报道不等于不限制**，检索时不得把 `not_reported` 当作"满足条件"。
- `evidence_tier`：T1 至 T4。T1 要求同时具备数值及单位、至少两个已报道的条件参数、块或表格单元格级锚点、引用文字回读通过。定性结论若原文有明确措辞也可给 T1（这一支叫"明确措辞支"）。T2 为一般定性；T3 为推测或跨体系外推；T4 为二手转述。
- `comparability_key`：由六个字段拼成：`指标|主方法|参比电极|孔型|AR 桶|面积基准`。只有 key 完全相同的两条 `Observation` 才允许比较大小、排序、判冲突。跨 key 一律回答"测量口径不同，不可直接比较"。

## 五、34 条边与 16 个谓词

边分四组：结构类（`HAS_BLOCK`、`NEXT`、`CITES`…）、事件类（`HAS_RUN`、`USES`、`HAS_ROLE`、`YIELDS`…）、概念类（`CONTAINS`、`HAS_MOTIF`、`OPERATES_BY`、`PRECEDES`、`EXPLAINS`、`DEFINES`…）、知识类（`ABOUT`、`SUPPORTED_BY`、`CONTRADICTS`、`AGGREGATES`…）。

`Claim` 的 `predicate`（谓词）只有 16 个，全部登记在 `schema.yaml#predicates`，每个带封闭的 slot 签名。例如：

| 谓词 | 允许的端点类型 | 是否必须带窗口 | 最高等级 |
|---|---|---|---|
| `improves` / `degrades` | Chemical 或 Motif → Indicator | 必须 | T1 |
| `has_role` | Chemical → Role | 可选 | T1 |
| `causes_defect` | Chemical 或 Run → 缺陷类型 | 必须 | T2 |
| `invalid_in` | Chemical → BathClass 或 Feature | 必须 | T2 |
| `analogous_to` | Chemical 或 Motif → Chemical 或 Motif | 可选 | T3 |

采用封闭注册表而不是自由文本，原因是：48 篇文献足以让同一含义演化出多种写法（"抑制""降低""减缓"），自由谓词会让按名称匹配的查询直接失效。未登记的谓词不进入图，进入待审清单。

## 六、51 条约束与三档处置

三档处置：

- `reject`：该条记录不进入图；
- `downgrade`：降低证据等级或改为定性表述；
- `warn`：保留，但打标记。

约束按主题分组，举四例说明其判定形式：

| 约束 | 判定 | 处置 |
|---|---|---|
| C-ANCHOR-01 | 断言没有锚点 | reject |
| C-EV-01 | 标 T1 但已报道条件参数少于 2 个（把 `condition_source.inherited` 也计入） | downgrade 至 T2 |
| C-CMP-01 | 两条结论 `comparability_key` 不同却比较大小或排序 | reject |
| C-TABLE-04 | 表的 `ocr_status` 为 `unreadable` 却产出数值型断言 | reject |

分布：断言层 30 项可判，图层 25 项可判，另有 3 条明确标注"待实现"（需化学性质或成分数据：酸碱相容、金属一致性、酸铜成分完整性），校验器会打印这 3 条的名字，不会伪装成已执行。

## 七、完整例子：从一张真实表格到五条记录

数据来自 `tables\1_s2_0_S0013468609007385_main__p3_0.csv`（第 3 页表 1，标题 *Plating formulas and filling results*）。CSV 中两行真实取值：

| Case | SPS (ppm) | PEG (ppm) | Cl⁻ (ppm) | DB (ppm) | Deposition mode | Surface appearance |
|---|---|---|---|---|---|---|
| 3 | 0.3 | 200 | 60 | 0 | Superfill | Bright but uneven |
| 6 | 0 | 200 | 60 | 1 | Conformal | Matte and rough |

抽取与归一化后应得到如下记录（字段名与 schema 一致；这是格式示例，本仓库不存实例数据）：

**① Block 与 Table（由清洗产物直接得到）**

```json
{"id":"blk:7f3a91c2d400ab68","type":"Block","doc_id":"1_s2_0_S0013468609007385_main",
 "block_type":"table","page":3,"bbox":[48,762,475,900],
 "section":"… > 3.1. Effect of DB addition on filling performance",
 "table_meta":{"n_rows":9,"n_cols":7,"csv":"tables\\1_s2_0_…__p3_0.csv",
               "class":"result","evidence":"text_layer","ocr_status":"confirmed"}}
```

**② Run（Case 6 那一行 = 一次条件组合）**

```json
{"id":"run:…:e3:r6","type":"Run","doc_id":"1_s2_0_S0013468609007385_main","exp_id":"…:e3",
 "conditions":[
   {"param":"concentration","of":"SPS","presence":"reported","kind":"point","value":0,"unit":"ppm","raw":"0"},
   {"param":"concentration","of":"PEG","presence":"reported","kind":"point","value":200,"unit":"ppm","raw":"200"},
   {"param":"concentration","of":"Cl-","presence":"reported","kind":"point","value":60,"unit":"ppm","raw":"60"},
   {"param":"concentration","of":"diazine black","presence":"reported","kind":"point","value":1,"unit":"ppm","raw":"1"},
   {"param":"temperature","presence":"not_reported"},
   {"param":"current_density","presence":"not_reported"}],
 "anchor":{"kind":"table_cell","doc_id":"…","page":3,"table_id":"tbl:…:p3:0","row":7,"col":0,"quote":"6"}}
```

`temperature` 记为 `not_reported` 而非留空：这张表的表头没有温度列，正文该节也未给出，因此是"文献未报道"，检索时必须输出为缺项。

**③ Observation（该行第 5 列的结果）**

```json
{"id":"obs:…:r6:mode","type":"Observation","indicator":"deposition_mode","outcome_kind":"qualitative",
 "categorical_value":"conformal",
 "method":["galvanostatic"],"reference_electrode":null,"doc_id":"…",
 "measured_at":{"kind":"table_cell","doc_id":"…","page":3,"table_id":"tbl:…:p3:0",
                "row":7,"col":5,"quote":"Conformal"},
 "comparability_key":"deposition_mode|galvanostatic|na|blind_via|na|na"}
```

**④ Claim（这句结论）**

```json
{"claim_id":"c:…:007","claim_kind":"observation_report",
 "doc_id":"1_s2_0_S0013468609007385_main",
 "subject":{"type":"Chemical","name_raw":"diazine black"},
 "predicate":"affects_indicator",
 "object":{"type":"Indicator","indicator":"deposition_mode","value":"conformal"},
 "window":{"params":[ …同 Run 的四个浓度… , {"param":"temperature","presence":"not_reported"}]},
 "condition_source":{"own":["concentration"],"inherited":["temperature","current_density"],"run_ref":"run:…:e3:r6"},
 "polarity":"assert","evidence_tier":"T2","stance":"support","quote_verdict":"supported",
 "anchors":[{"kind":"table_cell","doc_id":"…","page":3,"table_id":"tbl:…:p3:0","row":7,"col":5,
             "quote":"Conformal","quote_check":"exact"}],
 "extractor":{"model":"…","prompt_ver":"v1","date":"2026-10-19"},"review":"pending"}
```

这里 `evidence_tier` 是 **T2 而不是 T1**，原因有两点，都可以机器判定：

- 该结果没有数值（`Conformal` 是定性标签），走"明确措辞支"也不满足（原文没有"用作整平剂"这类表述）；
- 更要紧的是**这张表本身不能单独支撑"二嗪黑导致变差"**：Case 3 与 Case 6 之间同时变化了 DB（0→1）与 SPS（0.3→0）两个量。约束 C-EXP-01 要求条件型断言在 `window` 中写明这类混杂；当两行差异不止一个参数时，结论只能记为条件性（`polarity: conditional`）或降级。

若强行把 Case 3 与 Case 6 相比得出"DB 导致填充变差"，就违反了"在同一口径内比较"的要求，属于 C-CMP-01 与 C-EXP-01 要拦截的情形。

**⑤ EvidenceLink 与 KnowledgeUnit（以及本例为何不生成 KU）**

```json
{"id":"ku:…","type":"KnowledgeUnit","subject":{"type":"Chemical","ref":"chem:diazine_black"},
 "predicate":"affects_indicator","indicator":"deposition_mode",
 "effective_window":{"params":[{"param":"concentration","of":"diazine black","presence":"reported",
                                "kind":"range","lo":1,"hi":1,"unit":"ppm","raw":"1"}]},
 "support_class":"single_source","n_docs":1,"n_independent_runs":1,
 "comparability_key":"deposition_mode|galvanostatic|na|blind_via|na|na",
 "missing_params":["temperature","current_density"],"corpus_version":"2026-10-19"}
```

本例中该结论只来自 1 篇文献的 1 次运行，`support_class` 只能记为 `single_source`。若问答系统据此回答"推荐二嗪黑"，输出必须同时带上 `single_source` 与 `missing_params` 两项，否则就是把单篇线索当成共识。
