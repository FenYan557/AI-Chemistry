# 评估：schema 的可行性与性能（v1.0）

日期：2026-10-19 · 对象：`schema\`（24 节点 / 34 边 / 16 谓词 / 7 值对象 / **51 条约束**）
对齐的清洗快照：`02_清洗\out` 2026-10-19 00:30 版（blocks 5316 / chunks 6309 / tables 98）
口径：**只评 schema 能不能支撑"电镀添加剂选型 + 化学问答"，不评抽取模型好坏，也不产出图谱数据。**

## 0. 结论先行

| 维度 | 评分 | 一句话 |
|---|---|---|
| 表达力（能建模吗） | **8.5 / 10** | 选型、机理、负知识、拒答四类问题都有结构化落点；差的只是配方族与仪器细节 |
| 语料可获得性（填得满吗） | **6 / 10** | **这是真正的瓶颈**：温度 48% 篇有数值、面积基准 23%、表头 0/98 自带完整工况 |

| 可验收性 | **7.5 / 10** | 覆盖类指标能自动算；P/R 与拦截率必须人工金标 |

**结论：够做 1–6 篇试点，不能在全量 48 篇之前冻结 v1。**

## 1. 评估口径（先说清"我在算什么"）

| 维度 | 定义 | 怎么测 |
|---|---|---|
| **表达力** | 给定问题类型，schema 有没有字段承载答案 | 逐条对照六类题型（单跳/机理/选型/反事实/失败预测/拒答） |
| **可获得性** | 48 篇语料里这些字段真的填得出来多少 | `scripts/survey_corpus.py` 只读普查（正则可核） |
| **运行性能** | 校验器与检索的计算开销 | 合成数据压测 + 复杂度分析 |

**明确不测**（没金标就没法测，硬报数字就是编）：抽取精确率/召回率、规则拦截率与误杀率、冲突检出率。测法见 §6。

## 3. 语料可获得性（实测，48 篇 / 98 表）

### 3.1 正文层

| 指标 | 实测 | 对 schema 的含义 |
|---|---|---|
| 正文段落 | 2700 段 | block 覆盖率基线 |
| 含「数字+单位」候选句 | **1104 段（40.9%）** | 文本断言候选池，决定召回上限 |
| 提到参比电极 | **39/48（81%）** | `requires_ref_electrode` 大体可满足 |
| 给电流密度+单位 | **29/48（60%）** | `current_density` 可填，但"篇级命中"≠"每行都有" |
| 给温度+单位 | **23/48（48%）** | 温度会大量落 `not_reported` |
| 有波形/方法词 | **25/48（52%）** | 波形是这批文献最常漏的条件 |
| 说明面积基准 | **11/48（23%）** | 电流密度单位统一了，物理含义仍不可比 |

### 3.2 表格层（关键）

| 表头含 | 张数 |
|---|---|
| 浓度列 | 19/98 |
| 温度列 | 2/98 |
| 电流密度列 | 2/98 |
| 转速列 | 3/98 |
| 参比电极 | 0/98 |
| **浓度 + 电流密度同时有** | **0/98** |

表格共 456 个数据行（每张平均 4.7 行）、1433 个数值格。
含义：**表格给的是"被扫的那一列"，工况在正文实验部分**。任何要求"表格自带全条件"的规则都会把表格通道打死。

### 3.3 设计依据：普查数据直接支撑的六条规则

这六条不是"拍脑袋定的严格"，每一条都能对回上表的数字：

| # | 数据事实 | 由此确定的规则 |
|---|---|---|
| 1 | 表头几乎不自带工况（0/98 同时有浓度与电流密度） | **C-EV-01** 的 T1 条件数按 `own ∪ inherited` 计（工况从 Run 继承）；**C-EV-06** 要求继承必须给 `run_ref` 且 Run 上真是 reported |
| 2 | 面积基准只有 23% 篇说明 | **comparability_key** 含第 6 段 `current_basis`，且 `na ≠ geometric` |
| 3 | unreadable 3 张、partial 9 张、位图 4 张 | **C-TABLE-04**（unreadable 不得产数值）、**C-TABLE-05**（partial/位图最高 T2）；`Table.evidence` / `ocr_status` |
| 4 | 表块直挂 `csv/n_rows/header/class`，同页多表常见 | **C-TABLE-06**（Table/Block/CSV 三方维度一致）、**C-ANCHOR-05**（表块↔CSV↔table_id 可反查） |
| 5 | 块字段 `type` 与节点类名冲突；新增 `merged_from/split/part/caption_paired/no_number/raw_latex` | 图内改名 `block_type`；`Block`/`Figure`/`Equation` 字段与产物一一对应，`survey_corpus.py` 持续核对（当前未建模字段 = 0） |
| 6 | `retention.json` 给出逐篇文本层保留度 | `Document.cleaning_diagnostics`：回答时能说"该篇数值保留度 0.85"，召回异常篇目进人工复核 |

> 一条方法论提醒：首版温度正则末尾多写了个 `\b`，把 23/48 读成 4/48。**影响决策的数字必须换一种写法复核**，本脚本对温度同时用 °C 与 K 两种形态交叉验证。

## 4. 运行性能（实测）

压测环境：本机 Python 3.10，合成夹具（非真实语料），只反映校验器开销。

| 场景 | 规模 | 耗时 | 折算 |
|---|---|---|---|
| 断言层 `validate.py` | 500 条断言 | **2.41 s** | 4.8 ms/条（含解释器启动 + YAML 载入 + JSON Schema） |
| 图层 `validate_graph.py` | 5000 节点 / 15000 边 | **0.57 s** | 0.03 ms/边，线性 |
| schema 自检 `selfcheck.py` | 9 文件 | < 0.5 s | 适合 pre-commit |

复杂度：窗口求交 O(参数数)≈O(6)；选型扫描 O(KU 数)≈200；全库扫 claim≈1500，均毫秒级。
**48 篇规模不需要 Neo4j 撑性能**，Neo4j 的价值在 Cypher 路径查询与答辩演示。
唯一可优化点：JSON Schema 占断言校验大头，若上 5 万条再换 `fastjsonschema`。

## 6. 可行性风险（按影响排序）

| # | 风险 | 量化依据 | 缓解 |
|---|---|---|---|
| R1 | T1 分布偏低，排序信息不足 | 温度 48%、波形 52%、面积基准 23% | 条件按 own∪inherited 计；Experiment 级默认条件；KU 允许 T2 但标 `single_source` |
| R2 | 分子身份解析覆盖率低 | 多数为自合成新衍生物 | `unresolved` 一等公民；I3 退到 motif + 名称级 |
| R3 | 表格画像未定 | 52/98 `data_unnamed` | 人工 2 h，先做再 ETL |
| R4 | 位图/OCR 表数值不可靠 | unreadable 3、partial 9、位图 4 | C-TABLE-04/05：不可读不出数，partial 最高 T2 |
| R5 | 工况不可比 | 面积基准 23%、表头 0/98 双条件 | comparability_key 6 段 + 跨口径拒比 |
| R6 | 清洗与 schema 漂移 | enriched 未重跑；5807 vs 5316 差 491 | `survey_corpus.py` 做产物↔schema 对齐检查；`pipeline_version` 变更即重锚定 |
| R7 | 人工标注一致性 | 尚无标注手册 | 10 篇金标前先有手册，否则 P/R 站不住 |

## 7. 能验收什么、必须靠人工验什么

**能自动算**
- block 覆盖率 100%（orphan = 0）、断言锚定率 100%、quote 命中率三档
- 规则拦截分布（按 rule id 报 reject/downgrade/warn）
- KU 支持度分布（consensus / single_source / conflicting）、`missing_params` 频次
- 产物↔schema 字段对齐（`survey_corpus.py`，当前"未建模字段 = 0"）

**必须人工金标**（10 篇分层，双人标，报 Cohen's κ）
- 抽取 P/R（trigger / argument 分开报；跨节论元召回单列）
- 规则误杀率、冲突检出率与误报率

**不能证明**：语义无损。只能证明"信息单元级可寻址覆盖"。

## 9. 一句话总评

**schema 已不是瓶颈，语料可获得性、OCR 不可读表与人工投料才是。**
清洗产物里凡是有字段的，schema 都建了模（对齐检查为 0）；凡是有风险的（位图表、条件缺失、口径不一），都落成了约束而不是口头提醒。
