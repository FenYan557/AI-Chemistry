## 每篇文献的执行步骤

### 第 1 步：抽取（你亲自做）

读取该文献的 `out\extraction_input\{doc_id}.jsonl` 全部单元，按
`prompts\01_化学物质抽取提示词.md` 的规则抽取化学物质：

- 只抽：单质、化合物、离子、聚合物、添加剂商品名/代号
- 不抽：工艺名、方法名、设备、性能指标、泛泛类别词
- `span` 必须是输入文本的**逐字子串**，禁止改写翻译
- 缩写与全称同时出现各记一条（这是后面别名消歧的关键）
- 同一物质在同一块出现多次只记一次，取信息最全的 context
- 表格单元（`[TABLE ...]` 开头）的 context 必须带列语义：
  `在表'表题'中，物质名（浓度 X，作用：Y）`
- 图注单元只从图注文字抽，不臆测图形内容
- 拿不准的 `uncertain: true`，仍然输出

输出写入 `out\extraction\{doc_id}.json`（JSON 数组，格式见试点文件）。

### 第 2 步：PubChem 检索（跑脚本）

```powershell
cd E:\deeplearn\创新创业\Github仓库
python -X utf8 清洗/03_化学物质抽取消歧/scripts/pubchem_lookup.py
```

脚本对 `out\extraction\` 下全部唯一 span 查 PubChem 候选，结果在
`out\pubchem\candidates.jsonl`，带缓存可断点续跑。

注意事项：

- **需要网络**。沙箱内网络被拦截时脚本以前会静默产出全 no_candidate，
  现已加保护（连续 10 次网络失败报错退出）；看到该报错就用提权重跑
- 脚本已内置公式清洗：`Hg _2 SO _4` 这类带 `_` 的 span 会自动清理成
  `Hg2SO4` 再查，`query_term` 字段记录实际查询词
- 分子量规格代号（PEG-6000 等）自动剥后缀查通式并标 `spec_code`

### 第 3 步：消歧（你亲自做）

读 `candidates.jsonl` 中该篇 span 的候选，按 `prompts\02_消歧提示词.md`
逐条判定，写入 `out\disambiguation\{doc_id}.json`。五态：

- `matched`：唯一正确候选，给出 `pubchem_cid`
- `ambiguous`：多候选或语境不足，列 `alt_cids`
- `unmatched_new`：候选为空或全错
- `spec_of_general`：规格代号链通式 CID，`review_note` 注明规格
- `not_chemical`：复核后发现不是化学物质

**试点积累的判例，必须遵守：**

1. **缩写撞车**：PubChem 按缩写查到的候选常是无关物质
   （AP4A 查到的是 Diadenosine tetraphosphate）。此时用文中
   "全称(缩写)"的别名对照，链到全称 span 查到的 CID，
   撞车候选记入 `alt_cids`，`reason` 写明弃用理由
2. **图注来源保守**：`source_type=figure_caption` 的记录宁标
   `ambiguous` 不强行 matched（merge 时正文记录会覆盖，不会丢信息）
3. **离子写法**（Cl^-、Cu^2+、cobalt ions）选对应离子或最常见母体，
   理由写进 `reason`
4. **元素杂质**（如 TOF-SIMS 测的 N）链元素条目，`review_note` 注明语境
5. **电极/基底材料**（铂、硅、汞）正常链接
6. **绝不臆造 CID**。所有 CID 必须来自 candidates.jsonl，
   或来自同文献别名对的检索结果（并在 reason 说明）
7. 中文 span 若 PubChem 查不到，先试英文译名是**不允许的**
   （span 必须逐字）；查不到就 unmatched_new，review_note 注明"中文名未命中"

### 第 4 步：合并（跑脚本）

```powershell
python -X utf8 清洗/03_化学物质抽取消歧/scripts/merge_results.py
```

产出 `out\final\{doc_id}.json` 和 `out\final\_qc.json`。
检查该篇无 pending，向用户报告 matched/ambiguous/unmatched_new 数量
及 unmatched 的物质名单（供人工 review）。

## 执行纪律

- 一次做一篇，做完报告一篇，等用户确认再做下一篇
- 每篇开始先读它的 extraction_input 全部单元（通常 2~4 万字符），
  不要只读开头就抽
- 检索和合并脚本**处理的是全部文献的累积结果**，新篇的抽取 JSON
  放进 out\extraction\ 后重跑即可，缓存会跳过已查 span
- 发现新的判例类型（撞车、噪声、歧义新模式）时，追加到本文件的
  "判例"一节，并在报告中告知用户
- 不要修改 02_清洗 的任何产物；发现输入数据问题只记录报告

### 累积判例（试点 1~7 之外新增，务必沿用）

8. 聚合物名/缩写命中单体：PVP 只查到 6917（单体 N-Vinyl-2-pyrrolidone）、
   PEG 只查到 174（单体乙二醇）、Polyvinylpyrrolidone 直接无候选。
   聚合物不是单体，判 unmatched_new，把被弃用的单体 CID 留在 alt_cids，
   禁止因为"名字像"就 matched。
9. 聚合物牌号/等级代号（如 K30，PVP 的 Mw 等级）不在 pubchem_lookup.py 的
   SPEC_CODE 正则里，会命中无关同名条目（K30 → CID 24832038）。
   判 unmatched_new，review_note 写明它指代同篇哪个聚合物。
10. 水合分子式的 OCR 噪声：CoSO _4·7H_2 0、CoCl _2·6H_20 里水合数的字母 O
    被识别成数字 0，清洗后仍查不到 → unmatched_new + "建议人工补链"。
    不要手工改写 span（span 必须逐字）。
11. 同篇同义写法可借用 CID：某 span 自身无候选、但与同篇另一 span 明显同一实体时
    （cobalt cations ← cobalt ion 104729；gold / Au 同为 23985），允许借用其
    检索结果并在 review_note 写明来源，仍不得臆造 CID。
12. 写法变体只记一条：chloride ion / chloride ions、H_3 BO _3 / H_3BO_3
    这类同一实体的变体，抽最规范的一条，其余写进 review_note，避免下游重复实体。
13. 离子上标被吃成控制字符：个别 PDF 的 Cl 负离子在上标丢失后变成
    Cl + 控制字符 0x01。不要把控制字符放进 span，改抽正文里干净的全称
    （chloride ion），并在 review_note 记录该噪声；这属 02_清洗 的输入问题，
    只记录不改产物。
