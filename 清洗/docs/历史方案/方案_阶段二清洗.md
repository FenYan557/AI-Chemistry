## 二、阶段二的目标（只做四件事）

1. **删干净**：噪音、空块、非正文段——但每一次删除都可审计
2. **拼完整**：碎片合并到句末；不跨节、不跨页硬拼
3. **建结构**：章节路径、图表三件套、参考文献结构化、印刷页码
4. **切好块**：段内按句切、块内带 section 与页码，供检索与引用

## 三、规则清单

| 编号 | 规则 | 依据（实测） | 验收 |
|---|---|---|---|
| **C01** | 删 `header/footer/page_number/aside_text/page_footnote`；`ref_text` 不进正文但**结构化保留** | 5,168 块（47.1%） | 正文噪音 = 0；references 条数 ≥ 2,758 |

| **C03** | 碎片合并：**同页**相邻块合并，直到句末终止符；**跨页不合并**但标 `continues` | <80 字符 1,876 块 | 段数下降、句尾完整率 ≥95% |
| **C04** | 长段切分：>1,200 字符按句边界切成多段（保留原 bbox 与页码） | 86 段，最长 5,636 | 无 >1,800 字符的段 |

## 四、切块设计（为什么是 600/80，不跨节）

- **粒度**：Dense X Retrieval（[EMNLP 2024](https://aclanthology.org/2024.emnlp-main.845/)）证明"更细的检索单元（命题级）通常比整段更好"，但命题级需要额外的去上下文化代价；本项目折中取"句边界 + 600 字符"，既不切碎语义，也不让单块过长。
- **重叠 80**：防止跨句边界的条件（如"在 10 mg/L 时……"）被切断；重叠过大会引入重复命中，80 字符约等于 1–2 句的尾部。
- **不跨 section**：章节是领域内最强的检索先验（`3.2 Potentodynamic polarization` 这类标题本身就是查询词），跨节切块会把结论和其条件分开。
- **每块必带 `section + 物理页 + 印刷页`**：这是引用溯源（[ALCE](https://ojs.aaai.org/index.php/AAAI/article/download/29794/31374) 的 attribution 思路）的前提。
- 备选方案（不在本期实现）：命题级切块 + 去上下文化，需额外标注成本，留作后续对照实验。

## 五、评估方案

### 5.1 用哪些公开口径

| 环节 | 指标 | 来源 |
|---|---|---|
| 文本保真 / 阅读顺序 | 句子级召回、顺序正确率 | OmniDocBench（[arXiv 2412.07626](https://arxiv.org/abs/2412.07626)） |
| 表格还原 | 数值守恒率、TEDS 式结构一致性 | TEDS（Zhong et al., ECCV 2020） |
| 引用可溯源 | 可寻址率、页码准确率 | ALCE attribution |
| 切块质量 | 平均长度 / 跨节率 / 语义完整率 | 系统分析类工作（[ECIR 2025 chunking 系统分析](https://dl.acm.org/doi/abs/10.1007/978-3-032-21321-1_9)、[领域 RAG 切块研究](https://ieeexplore.ieee.org/abstract/document/11125724)） |
| 抽取就绪度 | 段完整率、论元可定位率 | DocEE（[NAACL 2022](https://aclanthology.org/2022.naacl-main.291/)） |

### 5.2 本阶段的自建验收（必须全部给出）

1. **删除可审计率 = 100%**（C12）——任何没登记的删除即视为缺陷
2. **噪音残留 = 0**；**空块 = 0**
3. **句尾完整率 ≥95%**（阶段一为 90% 的碎块）
4. **带 section 的块 ≥99%**
5. **无跨 section 的 chunk**；chunk 平均长度 400–700 字符
6. **数值不因清洗下降**：用阶段一的数值召回口径对清洗后重测，允许下降 ≤0.5%（清洗删的是噪音，不该删数值）
7. **图表引用可判定的比例**：C08 回填 / 拒绝数都报，不接受"静默跳过"

### 5.3 验证手段

- 确定性复检：`verify.py` 对清洗前后做例证对照
- 抽样人工：每篇抽 3 段核对（20 页级抽检）
- **可报销 key 逐篇复核**：把"被删除清单 + 清洗后表格"交给 A2lab 子智能体逐篇判断"有没有误删正文"，产出 `review/` 下的判定
