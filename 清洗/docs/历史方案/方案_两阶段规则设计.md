# 两阶段清洗方案（规则设计 v1）

> 依据：48 篇 MinerU 产物的全量扫描（`audit_defects.py`）+ 阶段一实测（`repair_stats.json`）+ A 组 16 篇逐篇 PDF 比对复核。
> **A 组复核结论（已验收）**：跨页拆表 0、表头错配 0（98 张表全量 colspan 校验）、正文串栏 0（启发式命中的 12 处全在首页标题/作者/目录区，bbox 复核正文顺序正确）、数值矛盾 0；**唯一实锤缺陷是「引用失配」15/16 篇**。
> 目标：**每一类缺陷都有明确归属（阶段一修／阶段二删／标缺失不补），且每条规则都能量化验收。**

## 0. 三条总原则

| 原则 | 含义 | 为什么 |
|---|---|---|
| **只修不删** | 阶段一只改错、补缺、打标记，绝不删除块 | 删除不可逆；修复可回滚 |
| **只删不改** | 阶段二只做"整块删除"和"块间合并"，不改块内文字 | 改字会静默污染数值 |
| **不确定就标** | 修不了的标 `sup_uncertain` / `no_number` / `unit_unknown`，不猜 | 错误标记能被下游过滤；猜测的错误不能 |

## 3. 三个专项

### 专项 A：引用失配（正文引 `Fig.N`/`Table N` 但无对应块）
三种可能，必须分清再动：
1. **图/表真漏抽** → 记 `missing_refs`，不补（补就是编造）
2. **caption 无编号**（R12 已标）→ 走 C08 保守回填
3. **编号错位**（正文按 Fig.1 起，图块从 Fig.2 起）→ 只标差异，不回填

产出：`out/report/ref_mismatch.csv`（篇名/期望编号/实际块/判定/动作）。**所有回填必须带 `inferred=true`。**

### 专项 B：单位下推（三级兜底）
```
① 列名里的单位（R07 已回填）
② 表题注括号里的单位
③ 同页紧邻正文最近一句中的单位
④ 都没有 → unit="unknown" + 数值仍保留，但进 KG 时降级为「无单位证据」，不生成断言
```
验收：`unit_unknown` 的数值格数要报出来（当前约 555 格），且**必须可列出清单**。

### 专项 C：条件字段的缺失语义
`参比电极` 缺失 ≠ 没做；必须区分：`未标注`（原文没写）/ `未识别`（可能漏抽，需人工看）。二者在 KG 中处理不同：前者降级可比性，后者是待办。

## 8. 表示层约定：Unicode / ASCII / LaTeX 各管一段

**结论：LaTeX 只保留给 equation 块，不作为任何东西的主表示。**

| 层 | 形式 | 用途 | 谁用 |
|---|---|---|---|
| `structured` | `{value: 1.5, unit: "mA/cm²", raw: "1.5 mA cm-2"}` | **主表示** | KG 抽取 |
| `text_index` | 纯 ASCII 归一（`mA/cm2`、`cm2`） | 检索匹配 | RAG / 全文检索 |
| `text_display` | Unicode（`mA·cm⁻²`、`ΔE`、`η`） | 人读 | 报告 / 界面 |
| `raw_latex` | 仅 equation 块保留 | 重排与核对 | 论文/公式复现 |

规则修订：

| 编号 | 修订内容 |
|---|---|
| **R02（收窄）** | 只转「符号 + 单位 + 简单上下标」；遇到 `\frac` `\int` `\sqrt` `\left(` 时**整块保留 LaTeX**，标 `math_kept_as_latex` |
| **R02b（新增）** | **绝不删未知命令**：不认识的宏原样保留并标 `unmapped_command`，清单必须为 0 才能交付（上次 `\Delta E`→`E` 的根因是"删"不是"转"） |
| **R02c（新增）** | 三字段输出：`text_display` / `text_index` / `raw`；任一缺失即算缺陷 |
| **R02d（新增）** | `raw_latex` 只写 equation 块；正文与表格**一律不落 LaTeX** |

不做全 LaTeX 的理由（实测支撑）：
1. 解析出的 LaTeX 本身有缺陷：`1. 9 5 4 2`（数字被空格拆）、`R _ {\mathrm{CT} (h k l)}`（下标混空格）、上标丢失 176 处——**全 LaTeX 会把这些错误格式化成"看起来正确"的样子**
2. 检索会退化：`\Delta\eta` / `\Delta \eta` / `\Updelta` 互不匹配，比 Unicode 更难归一
3. 四个下游消费者里只有一个（论文重排）需要 LaTeX

### 8.1 为什么不给"数学公式"找嵌入模型
- 通用嵌入（BGE / E5 / text-embedding-3）训练语料含 arXiv 源，见过 LaTeX，但 `\`、`{`、`\frac` 被切成碎片，`\mathrm`/`\left(` 这类零语义 token 稀释了向量
- 数学专用表征确实存在（MathBERT、Tangent-CFT、ARQMath 系列），但目标是**公式检索**（Presentation MathML/LaTeX 树之间找相似），用结构匹配优于 dense 向量；参见 Findings EMNLP 2022 对 token/passage 级 dense retrieval 在数学信息检索上的评估
- **我们要嵌入的是"描述公式的自然语言"，不是公式本身**。所以正确做法是把 LaTeX 从嵌入文本里剔除，而不是找能嵌入 LaTeX 的模型
